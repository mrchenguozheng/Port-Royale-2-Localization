## 二、质量偏低的地方

按严重度分三档。A 类是可以再修的真实问题，B 类是翻译策略上的取舍（改与不改都能说得通），

C 类是当前条件（无实机、控件宽度未知）下无法排除的隐患。

### A. 可以再修的（真实缺陷风险）



1. **无上下文单词条最易错义。** 这类条目只有一两个词，没有任何句子约束，只能靠零售德语里

   的共现实测反推。已经定过案的：`Stock`→`Bestand`、`Assets`→`Vermögen`、`Square`→`Platz`、

   `Layout`→`Anordnung`、`Annex`→`Annektieren`、`Amount`→`Betrag`、`Speech`→`Sprache`、

   `Condition`→`Zustand`。其中 `Layout`、`Annex`、`Speech` 三处法语给的是名词或不同义项

   （`Décors`／`Annexe`／`Voix`），已按英文与西 / 俄 / 波佐证否掉。仍属 "最可能出错的 8 条"，

   建议实机看一眼这几个按钮 / 表头实际指什么。

2. **自造复合词带直译感。** `Community building`→`Gemeinschaftsbau`、

   `Goods cache`→`Warendepot`、`Boarding crew`→`Entermannschaft`、

   `Floating Package`→`Treibende Kiste`、`Färbeplantage`、`Rumbrennerei`、`Seilerei`。

   这些词德语能懂，但不像原作会用的说法；原文多数是游戏自造的机制名，没有标准译法可依。

   `Färbeplantage` 尤其生硬（德语说 `Färberpflanze` 的种植园一般称 `Plantage`，不加前缀）。

3. **经济状态八档靠词面对撞，梯度比英文弱。** `Wealth`→`Wohlstand` 与

   `Riches`→`Reichtum` 只差一层语义；八档现为

   `Niedergang` / `Rezession` / `Stagnation` / `Erholung` / `Aufschwung` / `Blühende Wirtschaft` /

   `Wohlstand` / `Reichtum`。玩家要在这串词里读出 "从衰败到鼎盛" 的顺序，德语不如英文

   （`Vegetating` … `Flourishing`）直观。`Niedergang` 与 `Rezession` 的先后也容易被读反。

4. **数字读法在同一屏里混排。** 叙事句按德语习惯写数词（`eine Tagesreise`、

   `fünf Tagesreisen`、`zehnmal`），参数位（价格、炮数、吨位、`%1`）保留阿拉伯数字。

   结果是 "货物与价格总览" 这类教程里，同一段既有 `10 Fässer` 又有 `zehnmal`。

   口径是 "数值正确优先于字形一致"，但读起来确实不齐。

5. **键名与缩写本地化过头或不足。** `LMB/RMB`→`LMT/RMT` 在德语里并不通用

   （德语玩家更熟 `linke/rechte Maustaste`）；`Enter`→`Eingabetaste`、

   `Caps Lock`→`Feststelltaste`、`Shift`→`Umschalt` 是标准德语键名，但与键盘实物上的

   英文印字不一致，教程说 "按 Eingabetaste" 时玩家可能要愣一下。

6. **海盗威胁十档强弱梯度偏弱。** `Brave/Courageous/Daring`→`Tapfer/Mutig/Kühn`，

   德语这三个词的强度差没有英文明显，十档排下来中段几乎分不出高下。

7. **专名与零售版不一致，会与英文 / 零售攻略对不上。**

   `Kapitän Christian der Grausame`（零售作 `der Harte`）、

   `Lamar Bleibauch`（零售作 `Bleibauch Ben`）、`Schwarzer Adler`（Black Eagle 意译）。

   我们保留了 "船长" 头衔与更贴字面的译法，但玩家查攻略时名字对不上。

8. `dummy`**&#x20;系列改成了&#x20;**`Platzhalter`**。** 零售德语把它改成 `laberfasel?`（明显是调试期

   随手敲的），俄 / 西 / 法三份零售都原样留 `dummy`。判定它是填充式调试假文本，统一译

   `Platzhalter`；如果这串其实会显示在正式界面，那 `Platzhalter` 也只是一句 "占位符"。

### B. 有意的取舍（不算错，但读者能感觉到）



1. **把韵文改成了散文。** 藏宝诗谜原文押韵，德语为保住方位词可读性放弃了韵脚，

   读起来是分段散文而不是谜语诗。同理，"Holy August" 按法语落成 `Sankt August`。

2. **古体敬称&#x20;**`Ihr/Euch`**&#x20;与口语寒暄冲突。** 依据零售实测（`euch`×563、`euer`×183、

   `könnt`×223）统一用敬称，语法正确，但酒馆招呼（`Nehmt Platz`）、

   总督之女恋爱线（`Ihr könntet …?`）在 17 世纪加勒比语境里比英文的轻佻口吻疏远。

3. **火炮与船型术语离开字面。** `Grape shot`→`Kartätsche`、`Chain balls`→`Kettenschuss`、

   `carrack`→`Kraweel`。术语正确，但与英文原文的词形不再对应，中英对照时看不出是同一条。

4. **与既有 UI 文案对齐优先于字面。** `Docks`→`Handelsdock`（而非 `Dock`）、

   `Boom`→`Aufschwung`、`Recession`→`Rezession`。这是为了让长文里引用的按钮名

   和短标签批里定的界面名一字不差；代价是单词条本身略偏离字面。

5. **零售德语本身不可靠，全程没当底稿。** 零售 684 条（19.3%）与英文完全相同，

   81 条数字与英文不一致，还有译文混入引擎标识（`fonts`×177、`tiepolo`×129、

   `enddate`×112、`town`×93、`goods`×48）。所以我们的译文在术语上与零售有一批系统性差异，

   这是设计如此，不是缺陷；但玩家拿零售版攻略对照时会看到不一致。

### C. 当前条件下无法排除的（未验证）



1. **德语在游戏内一次都没有实机抽查过。** 目前只到编译与静态校验。

   全部排版判断都基于 "控件宽度未实测" 的前提，按用户既有约束没有用像素 / 字体宽度做判据。

   德语复合词长（`Handelsniederlassung`、`Gouverneurspalast` 这类），在 800×600 下

   换行次数必然多于英文，是否有控件被切、被省略号吃掉，静态校验查不出来。

2. **长文里大量引用的界面名未经视觉确认。** `Bestandsfenster`、`Konvoiliste`、

   `Handelsfenster`、`Dialog schließen`、`Übersicht und Kosten`、`Handelsnachweis`、

   `Baumenü`、`Szenarioziel`、`Ereignisfenster`、`Angriffsmodus` 等，

   都是按 en 语义新定的名字，其中一部分（如 `Trading Record`→`Handelsnachweis`）

   在界面上可能另有既有短标签，需要实机核对是否与屏幕文字一致。

3. **百科历史长文的语感。** 20 余篇 1000–2500 字符的历史 / 百科段落是全表最难的部分：

   德语性数格与从句语序在这种长句里最容易出机械感，逐条人工落笔也难以完全避免

   "翻译腔"。这类文本没有对照基准（零售版对应段本身就残缺），无法用交叉验证兜底。

4. `0x0512fa51`**（设置窗口标题）从未进过截图**，贸易 / 对话 / 公司管理界面也未抽查，

   这些界面的德语长标签是否会溢出仍未知。

print("占位不一致", len(bad), bad)
