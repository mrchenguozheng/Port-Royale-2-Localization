# アーキテクチャとリファクタリング計画

> 本書は、現在のレイヤー構成、既知のリスク、そして必要最小限の変更に留めるためのリファクタリング手順を記録したものです。
> 方針：言語の中央一覧は作らない、マイクロサービス化しない、プラグイン機構は作らない。

## 現在のレイヤー構成

```
PR2LauncherGUI.exe    言語の選択、別名の表示、フォントのチェック、locale.ini への書き戻し
        │
        ▼
PR2Launcher.exe      フォントのバックアップ、フォントディレクトリの決定、DLL の注入、PR2.exe の起動
        │
        ▼
PR2TextSource.dll    ゲームのテキスト取得のフック + フォントパスのリダイレクト + 言語パックの読み込み
```

ビルド側：

```
compile_pack.py      翻訳 → PR2Packs/<lang>.txt（# pack-meta 付き）
make_noto_fonts.py   Noto フォント → fonts/<lang>/*.TTF（キャッシュ付き）
make_release.py      リリースパッケージの組み立て
apply_patch.py       ローカルビルド + デプロイ
pr2ctl               エディタのインストール/デプロイ用バックエンド
```

## ファイル契約

| パス | 契約 |
|---|---|
| `PR2Packs/<lang>.txt` | `hash = text`；先頭に `# pack-meta alias=…` / `gui=…` を置ける；ゲームは `#` を無視する |
| `PR2Packs/locale.ini` | `language=<code>`；ゲームの既定言語であり、GUI が持つ唯一の言語状態 |
| `fonts/<lang>/` | ファイル名を固定した 4 つの TTF；フォントのみを置き、説明ファイルは置かない |
| `ui/<lang>.ini` | GUI のインターフェース翻訳；言語パックの `gui` メタデータで選択される |
| `PR2_PACK_LANG` | このプロセスでの言語の上書き；`--lang` が設定し、ファイルには書き込まない |
| `PR2_FONT_DIR` | このプロセスでのフォントサブディレクトリ；フォントが揃っているときに設定される |

## リファクタリング前のリスクと対応

| リファクタリング前のリスク | 対応 | 残っている境界 |
|---|---|---|
| フォント名/完全性チェックが散在 | `pr2_fonts.h` でランチャーと GUI を統一 | Python ビルドは出力ファイル名で書き込むため、C ヘッダーを共有しない |
| locale の意味が分岐 | `pr2_locale.h` で読み取りを統一；書き込みは GUI のみ | `PR2.exe` を直接実行するとランチャーを経由しない |
| ビルドの入口が多い | `build_artifacts.py` で言語パックとフォントを統一 | 実行時のファイルコピーは release/deploy がそれぞれ処理する |
| ファイル形式が暗黙的 | `min_runtime` で整数のバージョンチェックを追加 | 依然として最小限の形式で、schema もバリデータもない |
| 複数の言語パックがランタイムを上書き | `min_runtime` + `RUNTIME-VERSION` | `PR2.exe` の直接実行はチェックを迂回する；自動更新は行わない |

## リファクタリングの原則

- まず「同じルールを二重に書く」ことをなくす。抽象化を先に行わない；
- 共有コードには小さなヘッダーや小さなモジュールを使い、フレームワークは作らない；
- 言語状態のソースは `locale.ini` の一つだけにする；
- 言語パックは自己記述のまま維持し、中央一覧は作らない；
- 各ステップは単独でビルド、テスト、ロールバックできること。

## 段階的な計画

### ステップ 1：フォント契約の共有

- `src/injector/pr2_fonts.h` を追加する：
  - 4 つのフォント名；
  - `fonts/<lang>/` の完全性チェック。
- ランチャーと GUI が同じ実装を呼ぶように変更する；
- ランチャーが元から持つフォントバックアップもフォント名を再利用する；
- フォント欠落時とフォント完備時の両方の経路をビルドして検証する。

状態：完了。`pr2_fonts.h` がフォント名と完全性チェックを統一し、ビルドとフォント欠落時のフォールバックを検証済み。

### ステップ 2：locale の統一

- 最小限の locale 読み取り/書き戻し関数を抽出する；
- 明確にする：起動成功後に書き込むのは GUI のみで、CLI は読み取りのみ；
- GUI は言語状態のコピーを二重に持たない。

状態：完了。`pr2_locale.h` が読み取りと書き戻しを統一；書き込みは引き続き GUI のみ；CLI の直接起動と、GUI 起動後の書き戻しの両方を検証済み。

### ステップ 3：ビルド成果物の入口統一

- `make_release`、`apply_patch`、`pr2ctl` が同じ
  「言語パック + フォント + ランタイムのビルド」関数を共有するようにする；
- 既存ツールは書き直さず、重複したオーケストレーションだけを集約する。

状態：完了。`pack/build_artifacts.py` が言語パックのコンパイルとフォント生成を統一：
- リリース：`noto`、出力は `stage/fonts/<lang>/`；
- ローカル：`stitch`、出力は `build/fonts/<lang>/`。
実行時のファイルコピーは引き続き `make_release` / `pr2ctl` がそれぞれの対象に従って処理し、無理に統合しない。

### ステップ 4：ランタイムのバージョンチェック

- リリースパッケージにランタイムのバージョンを書き込む；
- 言語パックが要求する最低バージョンが一致しない場合、DLL/ランチャーが明確なエラーを報告する；
- 自動更新は行わない。

状態：完了。言語パックが `min_runtime` を書き込み、バージョンが低すぎる場合は GUI/ランチャーが起動を拒否する；
リリースパッケージは `RUNTIME-VERSION` を書き込む。整数バージョンのみで、自動更新は行わない。

## 検証ゲート

各ステップは少なくとも次を満たすこと：

1. `src\build_injector.bat` が成功する；
2. `python src\tools\check.py` が通る；
3. GUI を起動すると言語一覧が表示される；
4. `PR2Launcher.exe` を直接実行すると `locale.ini` に従ってゲームが起動する；
5. フォントが欠けている場合はルートディレクトリの元のフォントにフォールバックし、クラッシュしない。
