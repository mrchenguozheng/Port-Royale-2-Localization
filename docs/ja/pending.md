# 未対応項目

> **現在のサポート範囲：GOG 英語版 `1.1.2.3` のみ。** 以下に挙げる項目は、未サポートの
> ビルドや今後の方向性であり、現在のサポート範囲には含まれません。

まだ結論が出ていない問題、または調査方法は分かっているものの手を付けていない問題です。「今すぐ動けるか」の順に並べています。前半は**やり方は分かっていて、実行するだけ**のもの、後半は**方向性はあるが結論はない**ものです。

---

## 1. Steam 版：注入しても言語パックが有効にならない（最優先）

**症状**：Steam 英語版では `PR2Launcher.exe` でゲームを起動できますが、インターフェースは英語のままです。言語パックが差し替えられていません。GOG 英語版では同じ手順が問題なく動作します。

**確認済みの事項**：

- Steam 版の `PR2.exe` には Valve CEG の整合性検証があり、exe を 1 バイト変更するだけで
  `Application load error 3:0000065432` が発生します。したがって実行時注入しか手段がなく、ファイルは変更できません。
- 本プロジェクトの注入は**exe に書き込まない**ため、理論上は CEG に阻害されないはずです。
- Steam 版への注入はエラーを報告しませんが、**テキスト取得のフックが有効になりません**（UI のテキストが変わりません）。

**未調査の項目（疑わしい順）**：

1. **フックの固定オフセットが一致していない。** 現在のコードは GOG 版 `A2dLib-2.20A.dll` のオフセットから関数アドレスを取得しています。まず両バージョンでこの DLL のエクスポートテーブル／関数のエントリポイントを比較してください。これだけで「オフセットが誤っているのか」を直接判定できます。
2. **`A2dLib-2.20A.dll` の格納場所が異なる。** GOG ではゲームのルートディレクトリにありますが、Steam 版では同じ階層か、サブディレクトリにある可能性があります。DLL は遅延読み込みされるため、モジュールパスを解決できなければフックは失敗します。
3. **CEG の自己検証のタイミング。** 注入ポイントより前に CEG がプロセスを「整合性違反」とマークしていれば、注入した DLL は（クラッシュせずに）黙って無視される可能性があります。
4. **Steam 版には追加の DRM 層がある可能性**（SteamStub / CEG の二重ラップ）。そのためプロセスの起動経路が GOG と異なり、ランチャーのサスペンド→インジェクト→レジュームの流れを再検証する必要があります。

**判断のための最小実験**：Steam 版で「`PR2TextSource.log` を出力するだけの最小 DLL を注入する」という 1 点だけを行い、ログが書かれるかどうかを見ます。これで「注入が失敗した」のか「注入は成功したがフックが当たらなかった」のかを即座に切り分けられます。

## 2. GOG フランス語版はゲーム内で一度も検証していない

フランス語版 `1.1.2.42` の文字列テーブルは参照用として抽出済みです（`references\fr.gog_1.1.2.42.toml`）。ただし、**実際にフランス語版のゲームへパッチとして適用し、UI を通して動作を確認したことはありません**。

やるべきこと：GOG 英語版と同じ 3 ステップ（ビルド → ゲームディレクトリへ配置 → 起動）を実行し、次の 2 点に注目します。

- 注入が機能するか（言語パックが表示されるか）。
- フランス語版は英語版より文字列が 42 個多く、19 個少なくなっています。`n` タグとプレースホルダーのオフセットが依然として整合するか（`load_toml` はこの種のバージョン差をすでに許容していますが、フックは id でテーブルを引くため、実機での検証が必要です）。

## 3. フックがゲームのバージョンに依存している

コードは `A2dLib-2.20A.dll` 内の関数を固定オフセットで取得しています。ゲームのバージョンが変われば（GOG フランス語版や将来のパッチを含む）、オフセットを再特定する必要があり、そうしなければ一切動作しません。

長期的な方針：ハードコードされたオフセットではなく、**エクスポート名／シグネチャによる特定**に切り替えます。最低限でも「オフセット表」と「バージョン番号」の対応を記録し、バージョン変更時にどこを直すべきかが一目で分かるようにします。

---

## 4. 長い中国語の文が丸ごと表示されない

エンジンは単語をスペースで分割します。スペースを含まない漢字の連なりは幅超過の 1 単語として扱われ、**幅を超えた行は切り詰められずに丸ごと破棄されます**。そのため、エディタ上では問題なく見えても「この項目はゲーム内でまったく見えない」ということが時々起こります。

現状ではゲーム内で 1 項目ずつ確認するしかありません。緩和策として、「ウィジェットの幅から推定する」オフライン検査を用意し、明らかに長すぎる項目を先に検出する方法が考えられます。

## 5. フォントの合成とグリフのカバレッジ

ゲーム同梱のフォントには中国語のグリフがないため、`fonts\*.TTF` を置き換える必要があります。現在は `src\tools\font\fontstitch` が、元のラテン系フォントをベースにし、翻訳で使われる文字を供給元フォントから追加しています。言語ごとに `build\fonts\<language>\`（4 つのフォント、約 0.7〜1.3 MB）を持ち、他の言語とは独立しています。元のグリフ、文字幅、カーニング、name テーブルは変更しません。

「言語パックをコンパイル」すると自動で比較されます。翻訳によってフォントにない新しい文字が導入された場合、その言語の 4 つのフォントを再合成します。キャッシュの目印は `build\fonts\<language>\.stitch.json` です。

**ゲーム内検証（2026-10-22）**：メインメニューは中国語を正しく表示し、タイトルフォントにも中国語のグリフがあり、異常はありませんでした。

## 6. 旧セーブの名前が文字化けする（手動でのリネームのみ）

PR2.exe は ANSI のファイル API（`FindFirstFileA` など）しかインポートしていません。ファイル名の中国語はバイト単位で Latin-1 として解釈され、`×Ô¶´…` のように表示されます。

- 新しいオートセーブはすでに ASCII（`Autosave %02u`）に変更済みのため、文字化けしません。
- **既存の**中国語名のセーブファイルは依然として文字化けします。ASCII の名前にリネームしてください。
- 完全な修正には、エンジンの「ファイル名バイト → テキスト」という小さな処理をフックする必要があり、コストが高すぎるため現時点では行いません。

## 7. 英語原文に残っている `D774`（フランス語版に合わせて処理）

`0xd23b7fdf` の英語原文は次のとおりです。

```
<ts:80>Due to wear and tear, a %1 D774has sunk today on the trade route....
```

同じハッシュのフランス語版は次のとおりです。

```
<ts:80>En raison de son mauvais état, un %1 a coulé aujourd'hui alors qu'il était en transit....
```

フランス語版には `D774` がなく、文法的にも「a %1 sank」と読めます。したがって `D774` は英語版における**残留文字／タイプミス**です（初期のプレースホルダーが消し忘れられた可能性が最も高いです）。

対応：

- `references\en.gog_1.1.2.3.toml` は**そのまま維持します**（exe からそのまま抽出したものなので変更せず、将来の再抽出と比較できるようにします）。
- 中国語訳と日本語訳はいずれも `D774` を含めず、「a %1 sank」として訳しています。
- テーブル全体で `D774` を含む項目はこれ 1 件だけです（スクリプトで確認済み）。

## 8. 著作権表示は原文のまま保持する必要がある（`0xfc512ea5`）

この項目は第三者ライセンスの表示です。

```
Uses Miles Sound System, Copyright 1991-2004 by RAD Game Tools, Inc. MPEG Layer-3
playback supplied with the Miles Sound System from RAD Game Tools, Inc. MPEG Layer-3
audio compression technology licensed by Fraunhofer IIS and THOMSON Multimedia.
```

**翻訳しないでください**。英語のまま保持します。この種のテキストの翻訳は無意味であり、ライセンス表示の意味を変えてしまう可能性もあります。

これはハード制約としています。`compile_pack.py` の `KEEP_ORIGINAL` テーブルがコンパイル時に英語原文を強制します。翻訳が何と書かれていても上書きされ、警告が出力されます。後から同種の項目（他の第三者表示や商標表記）を追加する場合は、このテーブルにハッシュを追加するだけです。


## 隣接するプレースホルダー：「姓名」なのか書式文字列なのか

ゲーム内の多くの文字列は 2 つのプレースホルダーを並べて配置しています（`%1 %2`、`%2 %3`）。中国語／日本語では名と姓の間に `・` を入れますが、それはこの 2 つの位置が本当に名と姓である場合に限られます。「レベル＋名前」や「数量＋単位」であれば、`・` を入れるのは誤りです。

| ハッシュ | 判定 | 備考 |
|---|---|---|
| `0xE23F403A–D` | 名・姓（`%2・%3`） | `%1`=レベル、`%2`=名、`%3`=姓 |
| `0x200D4E11` | 名・姓（`%2・%3`） | 上と同じ。表示名の組み立てに使用 |
| `0x28B1F98D` | 名・姓（`%1・%2`） | 開始時の歓迎メッセージ。レベルは後で言及されるため、先頭 2 つが人名だと分かる |
| `0xCA6F7276` | 名・姓（`%2・%3`） | クエスト内の「誰某が英雄を募集している」 |
| `0xDBCAC2B1` | 名・姓（`%2・%3`） | レターヘッド `%1,<n>%2・%3` |

**未確定（現状のまま、`・` は追加しない）**：

| ハッシュ | 内容 | 判断できない理由 |
|---|---|---|
| `0xE7270933` | `<gs:TEXTFLUSS_KEINEHOEHE>%1  %2` | 数値スロットが 2 つ見えるだけで、文脈がない |
| `0xFFDC2433` | `<c>%1  %2` | 同上 |
| `0x08B186EF` | `<r>%1<n>%2   %3` | 同上。`<r>` は色タグ |
| `0x16656B80` | `%1 %2<g:scripts/intext_herz_800x600.screen>` | 「ハート」アイコンで終わる。2 つのスロットは数値の可能性がある |

### タグの意味

- `gs:` = グラフィックスクリプト命令。UI レンダラーが消費するもので、**翻訳対象のテキストではありません**。そのまま保持しないと、行のレイアウトやアイコンが失われます。
- `gs:TEXTFLUSS_KEINEHOEHE` はドイツ語です。`Textfluss` = テキストフロー、`Keine Höhe` = 固定高さなし、つまり「テキストが内容に応じて自動的にレイアウトされ、高さを確保しない」という意味です。レイアウトにのみ影響し、翻訳すべき字義はありません。
- `<c>`、`<r>`、`<n>` はそれぞれ色／赤／改行です。`<g:scripts/…>` は UI グラフィックを参照します（`intext_herz` は「ハート」アイコン）。

これら 4 件も確定させる唯一の方法は、ゲーム内でどの画面に現れ、その隣にどの数値が来るのかを確認することです。
