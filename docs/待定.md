## 1. Steam 版注入后语言包不生效（最优先）

**现象**：在 Steam 英文版上，`PR2Launcher.exe` 能启动游戏，但界面仍是英文，
语言包没有被替换进去。GOG 英文版同样的步骤一切正常。

**已经确认的**：

- Steam 版 `PR2.exe` 带 Valve CEG 完整性校验，改 exe 一个字节就报
  `Application load error 3:0000065432` —— 所以只能走运行时注入，不能改文件；
- 本项目的注入**不写 exe**，理论上不该被 CEG 拦；
- 在 Steam 版上注入没有报错，但**取字 hook 没有生效**（界面文本没变）。

**还没查的，按可疑程度排**：

1. **hook 的固定偏移对不上。** 现在的代码按 GOG 版 `A2dLib-2.20A.dll` 的偏移
   取函数地址。先比对两个版本这个 DLL 的导出表/函数起始位置有没有差异 ——
   能直接判定“是不是偏移错了”。
2. **`A2dLib-2.20A.dll` 的存放位置不同。** GOG 把它放在游戏根目录；Steam 版
   可能同级、可能在子目录。DLL 是懒加载的，模块路径取不到就等于 hook 失败。
3. **CEG 的自校验时机。** 如果 CEG 在注入点之前就把进程标记为“完整性异常”，
   注入的 DLL 可能被静默忽略（而不是崩溃）。
4. **Steam 版可能有额外的 DRM 层**（SteamStub / CEG 双壳），进程启动路径
   与 GOG 版不同，启动器的挂起-注入-恢复流程需要重新验证。

**判定的最小实验**：在 Steam 版上只做“注入一个打印 `PR2TextSource.log` 的
极简 DLL”，看日志有没有写出来 —— 能立刻区分「注入失败」还是「注入成功但
hook 没命中」。

## 3. hook 与游戏版本绑定

代码按固定偏移取 `A2dLib-2.20A.dll` 里的函数。换任何游戏版本（包括同是 GOG 的
法语版、或未来的补丁版）都可能需要重新定位偏移，否则整体不生效。

长期做法：改成**按导出名/特征码定位**，而不是写死偏移；至少要把「偏移表」与
「版本号」的对应关系记下来，换版本时一眼能看出要改哪。

## 4. 中文长句整条不显示

引擎按空格切词。整串汉字没有空格时会被当成一个超宽单词，**超宽的行是整条丢弃**，
不是截断。所以偶尔会出现「这一条在游戏里完全看不到」的情况，而编辑器里一切正常。

目前只能逐条实测。可考虑的缓解：给出一个“按控件宽度估算”的离线检查，
把明显超长的条目先标出来。

## 5. 字体裁剪与字形覆盖

游戏自带字体没有中文字形，必须替换 `fonts\*.TTF`；我们用的是按“当前译文用字”
裁过的版本（`build\fonts`，约 673 KB / 个）。

「构建所选语言」会自动比对：译文里出现新字而字体没有，就重裁四个字体。
**这条链路还没在真机上验证过“新字出现 → 重裁 → 游戏里正常显示”**，
目前只在离线校验里确认了字形确实被加进去。

## 6. 旧存档名乱码（只能手工改名）

PR2.exe 只导入 ANSI 版文件 API（`FindFirstFileA` 等），文件名里的中文会被
按 Latin-1 逐字节映射，显示成 `×Ô¶´…`。

- 新的自动存档已经改成 ASCII（`Autosave %02u`），不会再乱码；
- **已经存在的**中文名存档文件仍然会乱码，手动改成 ASCII 名字即可；
- 彻底修复需要 hook 引擎“文件名字节 → 文本”那一小段，代价较大，暂不做。

## 7. 原版英文的残字 `D774`（已按法语版处理）

`0xd23b7fdf` 的英文原文是：

```
<ts:80>Due to wear and tear, a %1 D774has sunk today on the trade route....
```

法语版同一 hash 是：

```
<ts:80>En raison de son mauvais état, un %1 a coulé aujourd'hui alors qu'il était en transit....
```

法语版没有 `D774`，且语法上是「一艘 %1 沉没了」，所以 `D774` 是英文版里的
**残字/笔误**（很可能是早期占位符没清干净）。

处理方式：

- `references\en.gog_1.1.2.3.toml` **保持原样**（那是从 exe 里原样提取的，
  不修改，便于以后重新提取时比对）；
- 中文、日文译文都按「一艘 %1 沉没」翻译，不带 `D774`；
- 全表只有这一条含 `D774`（已用脚本确认）。
