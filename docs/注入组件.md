# 注入组件

给《Port Royale 2》做本地化的运行时部分：**一个启动器 + 一个 DLL + 一个语言包目录**。

**不修改 `PR2.exe`。** 启动器把 DLL 注入游戏进程，DLL 在运行时接管引擎的取字调用，
把 `PR2Packs\` 里的译文送进去。原版 exe 全程只读。

源码在 `src\injector\`，编译脚本在 `src\`。

---

## 三个组成部分

| 文件 | 角色 |
|---|---|
| `PR2Launcher.exe` | 启动器。挂起方式启动 `PR2.exe`，注入 DLL 后恢复执行 |
| `PR2LauncherGUI.exe` | 图形界面。列出 `PR2Packs\*.txt`，选语言后调用上面的启动器 |
| `ui/<语言>.ini` | GUI 界面翻译（UTF-8 key=value）；由语言包 `# pack-meta gui` 选择 |
| `PR2Packs\<语言>.txt` 开头 | `# pack-meta alias=…` / `gui=…`；GUI 优先读这里，游戏忽略注释 |
| `PR2TextSource.dll` | 主逻辑。hook 引擎取字的三条路径，把译文替换进去 |
| `PR2Packs\` | 语言包目录。放语言包与配置，可直接改文本，无需重编译 |

---

## 工作方式

```
用户双击 PR2Launcher.exe   （或 GUI 用 --lang=xx 调它）
   │  CreateProcessA("PR2.exe", CREATE_SUSPENDED)
   │  VirtualAllocEx + WriteProcessMemory + CreateRemoteThread(LoadLibraryA)
   ▼
PR2.exe 载入 PR2TextSource.dll，DllMain → InstallHook()
   │
   ├─ LoadEditFile()      定语言（见下），载入 PR2Packs\<语言>.txt
   │
   ├─ hook #1  IAT：CStringManager::Add
   │            引擎注册主串表 (MISSION_NPC_GOODS_INFO) 时，
   │            replace_table() 把整张英文表重建成译文表
   │
   ├─ hook #2  vtable：CW32StringManager::AddStringRes / LoadStringRes
   │
   └─ hook #3  A2dLib::LoadStringRes 函数体
                兜住上面两条没覆盖到的查询；
                并把语言包没覆盖的 hash 连同引擎解析出的英文
                写进游戏目录下的 PR2TextSource_gap.log，供补译
```

DLL 做的事是**篡改进程内各模块的导入表**，把指向
`A2dLib-2.20A.dll!CStringManager::Add` 的格子换成自己 ——
于是引擎向它要字符串。注入本身是启动器干的，DLL 不创建远程线程。

译文查找只有**一个**来源 —— `PR2Packs\<语言>.txt`。命中即替换，
未命中交回引擎用原文。

## 语言包目录 PR2Packs\

```
PR2Packs\
├─ locale.ini     选哪个语言包
└─ zh.txt         简体中文，3548 条，格式：0x哈希 = 文本
                  （文件名即语言代码，可以有多个）
```

`locale.ini`：

```ini
language=zh          # 对应 PR2Packs\<语言>.txt，要与文件名一致
```

**语言代码从哪来**，`LoadEditFile()` 按这个顺序决定第一个可用的：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | 环境变量 `PR2_PACK_LANG` | 启动器 `--lang=xx` 写进子进程环境的，只影响这一次 |
| 2 | `locale.ini` 的 `language=` | 默认这条，GUI 的「启动语言」下拉读写的就是它 |
| 3 | DLL 内置的 `zh` | 连 ini 都没有时的兜底 |

第1 条与环境之间不需要任何 IPC：启动器给 `CreateProcessA` 传的环境块
是 `NULL`，意思是「继承我的」，所以 `SetEnvironmentVariableA` 设一次
`PR2.exe` 就有了。**不带 `--lang` 时环境变量不存在，行为与从前完全一样。**

```c
PR2Launcher.exe --lang=de     本次跑 de.txt，不改任何文件
PR2Launcher.exe               用 locale.ini 里的语言
PR2Launcher.exe --help
```

`--lang` 的值只允许字母、数字、连字符 —— 它要拼进
`PR2Packs\<代码>.txt`，放任 `../` 就是目录穿越，非法值报错退出。

**没有「基础语言包」这种东西。** 语言包里没有的 hash，游戏会显示它自己
内置的英文原文——引擎的那张主串表就是天然兜底，不需要额外准备。

改译文**不需要重编译**：编辑 `zh.txt` 保存，重启游戏生效。

## ⚠ 中文条目整条不显示 —— 成因是分词，不是标签

**引擎按空格切分单词。** 英文天然用空格分界，单词短、不易超宽；
中文没有空格，整串汉字连同标点会被当成**一个单词**去排版，
一旦超过该界面控件的可用宽度，**整条被丢弃** —— 不是截断，是完全不显示。

```
英文：Successful battles will boost your reputation more quickly with 5%.
      ^ 每个单词独立排版，短

中文：战斗获胜时，你的声望额外提高 5%。
      ^ 整串当成一个单词，超宽 → 整条丢弃
```

每个界面控件能放多宽都不一样，**没有通用值**，只能逐条在游戏里实测。
对策：在合适位置加 `<n>` 手动断行，或改用更短的措辞。

## 源码

| 文件 | 职责 |
|---|---|
| `pr2_text_source.cpp` | 主逻辑。三个 hook、整表替换、漏译捕获 |
| `pr2_text_pack.c` | 语言包加载器（纯 C89）。INI 解析、`hash = text` 解析、UTF-8→UTF-16 |
| `pr2_launcher.cpp` | 启动器。挂起启动 + 远程注入 |

`pr2_text_pack.c` 链入 DLL 一起编译，不单独产出。

### hook 的安全性

所有可能出错的操作都用 `__try/__except` 包住。失手时最多该串显示为空或回落英文，
不会崩游戏。

### 已知问题

- **hook 目标与游戏版本绑定。** 代码里查找
  `A2dLib-2.20A.dll` 的导出符号，并按固定偏移取函数体与单例：
  `ResolveByHash` 在 `+0x25C70`（其thunk 入口 `+0x1DC5`）、
  `g_pStringMgr` 在 `+0x142084`。
  换一个游戏版本时若这些不一致，hook 找不到目标，汉化整体不生效。
- **`FindOverride` 是线性查找**，且 `AddEdit` 不去重 —— 语言包内部若出现重复
  hash，返回的是先写入的那条。
- **加载失败静默。** ~~`LoadEditFile()` 失败时全部静默返回~~
  已修：`InstallHook()` 在 `EditLoaded() == 0` 时会写一行
  `NO pack loaded: language 'xx' from <目录>`。以前这个失败在屏幕上
  完全看不出来（现象与「没汉化」一致），现在看日志第一行即可判断。

## 日志

写在游戏目录，全部由 `PR2TextSource` 命名：

| 文件 | 内容 |
|---|---|
| `PR2TextSource.log` | 首行 = 实际加载的语言包与条目数；加载失败时首行是 `NO pack loaded: …` |
| `PR2TextSource_gap.log` | 语言包没覆盖的 hash + 引擎解析出的英文，供补译 |
| `PR2TextSource_lsr.log` | vtable 那条 hook 的记录 |
| `PR2TextSource_resolve.log` | `ResolveByHash` 的记录 |
| `PR2FontPaths.log` | 设 `PR2_FONT_LOG=1` 时记录游戏读取的字体路径；`PR2_FONT_LOG_ALL=1` 记录全部文件 API |

`gap.log` 是补译的主要线索来源。

## 字体备份与切换

启动器在第一次替换字体前，会把原版四个 TTF 备份到：

```
fonts\_original\
```

只认已知的原版大小 + SHA-256，所以即使根目录已经被 Noto 覆盖，也不会把
Noto 误存成原版；恢复前也会再校验备份的哈希。

- **根目录保留原版字体，不覆盖**；
- 本地化启动：如果 `fonts\<语言>\` 存在，启动器设置 `PR2_FONT_DIR=<语言>`，
  DLL 把 `fonts\ARIAL.TTF` 等重定向到 `fonts\<语言>\`；
- 原版启动：`PR2Launcher.exe --vanilla` 不设置重定向，直接使用根目录原版；
  如果根目录已被替换过，会先从 `fonts\_original\` 恢复。

重定向只在文件 API 层生效（`fopen` / `CreateFileA/W` / `FindFirstFileA` /
`GetFileAttributesExA`），不改游戏文件。

日志：

```bat
set PR2_FONT_LOG=1
PR2Launcher.exe --lang=zh
```

`PR2FontPaths.log` 里会看到改写后的 `fonts\zh\ARIAL.TTF` 等路径。

`PR2TextSource.log` 的**第一行是确认汉化是否生效的唯一依据** ——
游戏跑起来后先看它：

```
[text] pack 'zh' from C:\Games\Port Royale 2\PR2Packs  (3548 entries)
```

看到这种行 = 语言包找到了、汉化已生效，屏幕上的中文就是它给的。
首行是 `NO pack loaded: language 'xx' from <目录>` = 那个目录下没有
`<xx>.txt`，DLL 退回引擎自带表，屏幕上就是原版英文。

## 编译

需要 Visual Studio（C++ 桌面开发组件）。

```
src\build_injector.bat
```

脚本会自行定位 MSVC 与 Windows SDK，产物输出到仓库根的 `build\`。
**目标架构是 x86** —— PR2 是 32 位进程，hook 代码依赖 32 位调用约定。

也可以在「x64 Native Tools Command Prompt for VS」里手动执行：

```
cd src\injector
cl /nologo /MT /LD /Ox /W3 /utf-8 /D_CRT_SECURE_NO_WARNINGS ^
   pr2_text_source.cpp pr2_text_pack.c ^
   /Fe:PR2TextSource.dll /link /OUT:PR2TextSource.dll psapi.lib

cl /nologo /MT /Ox /W3 /utf-8 /wd4819 /D_CRT_SECURE_NO_WARNINGS ^
   pr2_launcher.cpp ^
   /Fe:PR2Launcher.exe /link /OUT:PR2Launcher.exe
```

`/utf-8` 和源文件的 UTF-8 BOM 都不能省：少了它们，`cl` 会按代码页 936
读源文件，中文字面量在编译期就被截断（`到` 会变成半个字节），
启动器的中文提示全是乱码。`/wd4819` 抑制的是 `/utf-8` 下仍然会报的
C4819 误报 —— 字面量本身是完好的。
