# 注入组件

给《Port Royale 2》做本地化的运行时部分：**一个主逻辑 DLL + 一个语言包目录 + 一个启动器**。
GOG 和 Steam 的正式入口都是 `PR2LocalizationGUI.exe` / `PR2Localization.exe`：启动器先判版，
GOG 注入 `PR2LocalizationCore.dll`，Steam 先把宿主 `Ascaron.Logging-2.6.dll` 代理挂上再直启
`PR2.exe`。Steam 的代理由 `PR2.exe` 静态导入，不再使用 `VERSION.dll`。

**不修改 `PR2.exe`。** GOG 直启 `PR2.exe` 时，加载器会把 `VERSION.dll` 解析到
`C:\Windows\SysWOW64\VERSION.dll`，本项目的同目录代理不会进入进程；因此 GOG
必须走启动器注入。Steam 的宿主 DLL 在启动前由启动器调 `PR2HostMount.ps1`：
先校验原版大小/SHA-256、备份，再换名替换（先写 `.new`、校验、再 `Move-Item` 覆盖，
失败时原文件不变）；还原是同一套动作的反向。主逻辑在运行时接管引擎的取字调用，把 `PR2Localization\packs\` 里的译文送进去。
原版 exe 全程只读。

源码在 `src\injector-rs\`（Rust workspace），编译脚本在 `src\`。

---

## 组成部分

| 文件 | 角色 |
|---|---|
| `Ascaron.Logging-2.6.dll` | Steam 宿主代理。原版由 `PR2.exe` 静态导入，只有一个 `Log` 导出；代理接管 `Log`，并创建线程加载同目录 `PR2LocalizationCore.dll`。包内放在 `PR2Localization\host\`，只在挂载时换进根目录。挂载/还原由启动器调 `PR2HostMount.ps1`，脚本做大小与 SHA-256 校验，代理与原版都经临时文件换名写入，每一步写 `PR2Localization\logs\host.log`。GOG 不使用它 |
| `PR2LocalizationCore.dll` | 主逻辑。等待 `A2dLib-2.20A.dll` 后 hook 引擎取字的三条路径，把译文替换进去 |
| `PR2Localization.exe` | 统一启动器。判出 GOG 就挂起 `PR2.exe` 注 DLL 再恢复；判出 Steam 就先确保宿主代理在位，再直启 `PR2.exe`。支持 `--lang`、`--vanilla` 和 `--restore` |
| `PR2LocalizationGUI.exe` | 图形界面入口（两版共用）。列出 `PR2Localization\packs\*.txt`，选语言后调用上面的启动器；Steam 版多一颗「还原 Steam 原版」按钮；退出卡死时可结束本目录的 `PR2.exe` |
| `ui/ui.default.ini` | 启动器默认界面（UTF-8 key=value）；用户 `ui.ini` 按项覆盖 |
| `PR2Localization\packs\<语言>.txt` 开头 | `# pack-meta alias=` / `min_runtime=` / `version=` / `entries=` / `untranslated=` / `scope=` / `digest=`；GUI/启动器读，游戏忽略注释 |
| `PR2Localization\packs\` | 语言包目录。放语言包与配置，可直接改文本，无需重编译 |

## 工作方式

```
GOG：PR2LocalizationGUI.exe / PR2Localization.exe
  │  挂起创建 PR2.exe → 远程注入 PR2LocalizationCore.dll → 恢复执行
  ▼
PR2LocalizationCore.dll，DllMain → InstallHook()

Steam：PR2.exe
  │  静态导入 Ascaron.Logging-2.6.dll
  ▼
Ascaron.Logging-2.6.dll（本项目宿主代理）
  │  接管 Log 导出，转发给 Ascaron.Logging-2.6.orig.dll
  │  DllMain → CreateThread → 等待 A2dLib → LoadLibraryW(".\\PR2LocalizationCore.dll")
  ▼
PR2LocalizationCore.dll，DllMain → 创建初始化线程 → InstallHook()
  │
  ├─ LoadEditFile()      定语言（见下），载入 PR2Localization\packs\<语言>.txt
  │                      再载入可选的 PR2Localization\packs\overrides\<语言>.txt
  │
  ├─ 启动重试线程：每 250ms 查 A2dLib，最多 120 次（约 30 秒）
  │    A2dLib 未加载时只记一次日志，不放弃
  │
  ├─ hook #1  IAT：CStringManager::Add
  │            引擎注册主串表 (MISSION_NPC_GOODS_INFO) 时，
  │            replace_table() 把整张英文表重建成译文表
  │
  ├─ hook #2  vtable：CW32StringManager::AddStringRes / LoadStringRes
  │
  └─ hook #3  A2dLib 的 CScreenStrings::ResolveByHash thunk
                 thunk 在 A2dLib 基址 +0x1DC5，真实函数体在 +0x25C70；
                 先校验 thunk 的 E9 确实跳到 +0x25C70，未知构建只记日志
                 [R] 记到 resolve.log，[RGAP] 记未命中的 hash + 引擎原文
```

DLL 做的事是**篡改进程内各模块的导入表**，把指向
`A2dLib-2.20A.dll!CStringManager::Add` 的格子换成自己 ——
于是引擎向它要字符串。GOG 由启动器负责把 DLL 注入进程；Steam 由宿主代理
在工作线程里加载它。

`PR2Localization.exe` 是两版共用的入口：判出 GOG 时保留挂起 + 远程注入路径，判出 Steam 时
先挂宿主代理再直启游戏；都支持显式 `--lang`、`--vanilla`，另有 `--restore` 只做还原。
GOG 直启 `PR2.exe` 不会加载同目录 `VERSION.dll`。
Steam 由启动器在启动前替换宿主 DLL 并直接拉起 `PR2.exe`，不需要从 Steam 客户端启动。

Steam 版经过启动器启动时，`PR2_FONT_DIR` 和 `PR2_PACK_LANG` 由启动器设好，与 GOG 一致；
只有绕过启动器、直接双击 `PR2.exe` 时才会走下面这条没有 `PR2_FONT_DIR` 的回退。

`g_pStringMgr` 优先从 `A2dLib` 导出
`?g_pStringMgr@NA2dLib@@3PAVCStringManager@1@A` 读取；固定 `+0x142084`
只作为 fallback，不再作为唯一依据。

Steam 绕过启动器直接双击 `PR2.exe` 时没有启动器设置 `PR2_FONT_DIR`，DLL 会回退到
`PR2Localization\fonts\` 的四份平铺字体；该目录不存在时继续用根目录原版字体，行为与启动器启动一致。
GOG 同样由启动器设置字体目录，不需要依赖这条回退。

译文查找的来源是**基础包 + 可选 override**：先读 `PR2Localization\packs\<语言>.txt`，
再读 `PR2Localization\packs\overrides\<语言>.txt`；命中即替换，未命中交回引擎用原文。
`overrides` 里的同 hash 条目覆盖基础包，适合本机临时改几句、不提交。

## 语言包目录 PR2Localization\packs\

```
PR2Localization\packs\
├─ locale.default.ini  发行包默认语言
├─ locale.ini          用户选择；存在即优先（可为空）
├─ zh.txt              简体中文，3548 条，格式：0x哈希 = 文本
│                      （文件名即语言代码，可以有多个）
└─ overrides\
   └─ zh.txt           可选：本机临时覆盖，格式同上；同 hash 覆盖 zh.txt
```

`overrides\` 是**可选目录**，不会出现在启动器 GUI 的语言列表里：
GUI 只枚举 `PR2Localization\packs\*.txt`，而 override 在子目录中。hook 在读完
`zh.txt` 后按精确路径再读 `overrides\zh.txt`，后者里的同 hash 条目生效。
安装/部署只清理过期语言包，`overrides\` 整个子树保留。

`locale.ini` 是用户选择；发行包只带 `locale.default.ini`。活动文件存在即优先，
`language=` 为空也算用户明确清空，不会被默认值补回。形如：

```ini
language=zh          # 对应 PR2Localization\packs\<语言>.txt，要与文件名一致
```

`=` 两侧允许空白，值后的 `;` / `#` 视为行内注释；Rust 运行时与 Python 工具
使用同一套解析规则。写回时只保留一行 `language=<代码>`，不会在文件头再插一行。

空值只表示“文件里没有语言代码”，不等于原版英文；注入后的运行时仍会落到 DLL 内置的
`zh`。原版入口是 `PR2Localization.exe --vanilla` 或 GUI「启动原版」。

**语言代码从哪来**，`LoadEditFile()` 按这个顺序决定第一个可用的：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | 环境变量 `PR2_PACK_LANG` | 启动器 `--lang=xx` 写进子进程环境的，只影响这一次 |
| 2 | `locale.ini` 的 `language=` | 用户选择；发行版 GUI 写它 |
| 3 | `locale.default.ini` 的 `language=` | 活动文件不存在时的发行默认 |
| 4 | DLL 内置的 `zh` | 两个文件都缺失，或活动/默认值为空、代码无效时的兜底 |

第1 条与环境之间不需要任何 IPC：启动器给 `CreateProcessA` 传的环境块
是 `NULL`，意思是「继承我的」，所以 `SetEnvironmentVariableA` 设一次
`PR2.exe` 就有了。**不带 `--lang` 时环境变量不存在，行为与从前完全一样。**

```c
PR2Localization.exe --lang=de     本次跑 de.txt，不改任何文件
PR2Localization.exe               用活动 locale.ini（缺失时读 locale.default.ini）
PR2Localization.exe --help
```

`--lang` 的值只允许字母、数字、连字符 —— 它要拼进
`PR2Localization\packs\<代码>.txt`，放任 `../` 就是目录穿越，非法值报错退出。

**没有「基础语言包」这种东西。** 语言包里没有的 hash，游戏会显示它自己
内置的英文原文——引擎的那张主串表就是天然兜底，不需要额外准备。

改运行包里的文本**不需要重编译**：直接编辑 `PR2Localization\packs\zh.txt`，或把修改写进
`PR2Localization\packs\overrides\zh.txt`，重启游戏生效。仓库里的 TOML 源文件仍要通过
`quick.py` / `compile_pack.py` 生成运行包，override 不会被构建覆盖。

## ⚠ 中文条目整条不显示 —— 成因是分词，不是标签

**引擎按空格切分单词。** 英文天然用空格分界，单词短、不易超宽；
中文没有空格，整串汉字连同标点会被当成**一个单词**去排版，
一旦超过该界面控件的可用宽度，**整条被丢弃** —— 不是截断，是完全不显示。

```
英文：Successful battles will boost your reputation more quickly with 5%.
      ^ 每个单词独立排版，短

中文：战斗获胜时，你的声望额外提高 5%。
      ^ 整串当成一个单词，超宽 → 整条丢弃
```

每个界面控件能放多宽都不一样，**没有通用值**，只能逐条在游戏里实测。
对策：在合适位置加 `<n>` 手动断行，或改用更短的措辞。

## 源码

Rust workspace 在 `src\injector-rs\`，五个 crate：

| 文件 | 职责 |
|---|---|
| `pr2_common/src/lib.rs` | 公共路径、`locale.ini`/`locale.default.ini`、语言包版本检查、字体完整性检查 |
| `pr2_proxy/src/lib.rs` | 旧 `VERSION.dll` 代理：转发 version API；Steam 发行包已改用宿主 `Ascaron.Logging-2.6.dll` |
| `pr2_text_source/src/lib.rs` | DLL。三个 hook、整表替换、漏译捕获、A2dLib 延迟重试 |
| `pr2_launcher/src/main.rs` | GOG 正式启动器。挂起启动 + 远程注入 + 字体备份/恢复 |
| `pr2_launcher_gui/src/{main,gui,packs,process,strings}.rs` | Win32 GUI。窗口/布局、语言列表、启动/结束进程、默认 UI + 用户覆盖 |
| `ui/ui.default.ini` | 启动器默认界面，构建时复制到 `build\runtime\ui\` |

旧的 C++ 实现已移出工作树，当前文档不再保留文件级对照；需要查当时的文件名和迁移细节，
见[历史重构记录](历史重构记录.md)。

### hook 的安全性

Rust 版去掉了 SEH（`__try/__except`），改用 `VirtualQuery` 检查目标地址是否可读，
再访问候选 vtable / thunk。它比 C++ 版更保守：读不到就跳过该 hook，不强行写入；
失手时最多该串显示为空或回落英文，不会崩游戏。

### 已知问题

- **hook 目标与游戏版本绑定。** `ResolveByHash` 的 thunk 偏移
  `+0x1DC5`、真实函数体 `+0x25C70` 仍按 A2dLib-2.20A 的已知 profile 校验：
  只有 thunk 的 `E9 rel32` 确实跳到该目标才 patch，未知构建只记日志、不盲写。
  `g_pStringMgr` 优先用导出符号定位，`+0x142084` 只是 fallback。
  换一个游戏版本时若这些不一致，hook 找不到目标，汉化整体不生效。
- **覆盖查找是哈希表**；`AddEdit` 对同 hash 采用**后写覆盖**。基础包先加载，
  `overrides\<语言>.txt` 后加载，所以 override 会赢。
- **加载失败静默。** ~~`LoadEditFile()` 失败时全部静默返回~~
  已修：`InstallHook()` 在 `EditLoaded() == 0` 时会写一行
  `NO pack loaded: language 'xx' from <目录>`。以前这个失败在屏幕上
  完全看不出来（现象与「没汉化」一致），现在看日志第一行即可判断。

## 日志

写在游戏目录。主逻辑日志由 `PR2LocalizationCore` 命名，代理日志单独一份：

| 文件 | 内容 |
|---|---|
| `PR2Localization\logs\proxy.log` | 代理加载结果：`loaded PR2LocalizationCore.dll` 或系统 version.dll / 主逻辑 DLL 的失败原因 |
| `PR2Localization\logs\runtime.log` | 首行 = 实际加载的语言包与条目数；加载失败时首行是 `NO pack loaded: …` |
| `PR2Localization\logs\vtable.log` | vtable 那条 hook 的记录（最多 5000 条） |
| `PR2Localization\logs\resolve.log` | `ResolveByHash` 的 `[R]` 记录（进程启动时 truncate，最多 8000 条）；`[RGAP]` 是没被语言包覆盖的 hash + 原文，去重最多 2048 条 |
| `PR2Localization\logs\font-paths.log` | 设 `PR2_FONT_LOG=1` 时记录游戏读取的字体路径；`PR2_FONT_LOG_ALL=1` 记录全部文件 API |

`resolve.log` 里的 `[RGAP]` 是补译的主要线索来源。

## 字体备份与切换

启动器在第一次替换字体前，会把原版四个 TTF 备份到：

```
PR2Localization\fonts\_original\
```

只认已知的原版大小 + SHA-256，所以即使根目录已经被 Noto 覆盖，也不会把
Noto 误存成原版；恢复前也会再校验备份的哈希。

- **根目录保留原版字体，不覆盖**；
- **默认映射 + 用户按项覆盖**：发行包提供 `PR2Localization\fonts\font-map.default.ini`，
  把 `fonts\ARIAL.TTF` 等逻辑名映射到 `PR2Localization\fonts\` 内的实际字体文件名；
  用户可另建 `font-map.ini`，只写要覆盖的项；运行时先默认后用户，解压升级不覆盖它；
  值只取文件名，不接受字体目录之外的路径，也不读系统字体目录；
- 内置字体：如果四个逻辑名都能映射到 `PR2Localization\fonts\` 内真实存在的文件，
  启动器设置 `PR2_FONT_DIR=<语言>`，DLL 把 `fonts\ARIAL.TTF` 等重定向到实际文件；
- 原版启动：`PR2Localization.exe --vanilla` 不设置重定向，直接使用根目录原版；
  如果根目录已被替换过，会先从 `PR2Localization\fonts\_original\` 恢复。

配置文件格式（`[fonts]` 是全局默认，语言节覆盖它）：

```ini
[fonts]
; 可选的全局默认

[zh]
ARIAL.TTF=NotoSansSC-Regular.ttf
ELGRECO_.TTF=NotoSerifSC-Black.ttf
Tiepolo_black.ttf=NotoSerifSC-Black.ttf
Tiepolo_bold.ttf=NotoSerifSC-Bold.ttf
```

四个槽位分别映射；实际文件必须位于 `PR2Localization\fonts\`，文件名可保留
Noto 原始名称，两个槽位可以指向同一文件。只接受静态字重，不使用 `.ttc` 或
`-VF.ttf`；解析器会跳过这两类候选。映射缺失或文件不存在时，运行时回退到
根目录原版，不会因为缺一个映射就拒绝启动。

注意：现有重定向按单个文件名/路径生效；如果游戏用
`FindFirstFileA("fonts\\*.*")` 枚举目录，配置映射不会把原目录虚拟成字体映射目录是否发生枚举以 `font-paths.log` 为准；枚举场景仍需要内置字体或扩展 hook。

重定向只在文件 API 层生效（`fopen` / `CreateFileA/W` / `FindFirstFileA` /
`GetFileAttributesExA`），不改游戏文件。

日志：

```powershell
$env:PR2_FONT_LOG = 1
.\PR2Localization.exe --lang=zh
```

`PR2Localization\logs\font-paths.log` 里会看到最终传给文件 API 的路径：
`PR2Localization\fonts\NotoSansSC-Regular.ttf` 等实际文件路径；出现它们说明
重定向和映射已生效。

`PR2Localization\logs\runtime.log` 的**第一行是确认汉化是否生效的唯一依据** ——
游戏跑起来后先看它：

```
[text] pack 'zh' from C:\Games\Port Royale 2\PR2Localization\packs: 3548 overrides
```

看到这种行 = 语言包找到了、汉化已生效，屏幕上的中文就是它给的。
首行是 `NO pack loaded: language 'xx' from <目录>` = 那个目录下没有
`<xx>.txt`，DLL 退回引擎自带表，屏幕上就是原版英文。

## 编译

需要 Rust（rustup）和 `i686-pc-windows-msvc` target：

```powershell
rustup target add i686-pc-windows-msvc
.\src\build_injector.ps1
```

`src\injector-rs\.cargo\config.toml` 已把默认 target 钉成
`i686-pc-windows-msvc`；脚本执行 `cargo build --release --locked`，然后把
`PR2LocalizationCore.dll`、`PR2Localization.exe`、`PR2LocalizationGUI.exe` 和 `PR2Localization\ui\*.ini`
复制到仓库根的 `build\runtime\`。

**目标架构是 x86** —— PR2 是 32 位进程，hook 代码依赖 32 位调用约定。
`PR2LocalizationGUI.exe` 用 `#![windows_subsystem = "windows"]` 编译，双击不会弹控制台。

手动编译：

```powershell
Set-Location src\injector-rs
cargo build --release
```

产物在 `src\injector-rs\target\i686-pc-windows-msvc\release\`。
