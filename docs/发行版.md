# 发行版

## 支持的游戏版本

**GOG 英文版 `1.1.2.3` 已实测；Steam 英文版 `1.1.2.3` 已实测（宿主 DLL 代理，
中文界面）。** 其余版本按语言分别验证：GOG 法语 `1.1.2.42` 的键集已纳入出包
（译文层按并集组织，见[译文与语言包](译文与语言包.md)），但该版本尚未实机验收；
没验收过、也没有对应键集数据的版本不要部署。以后是否支持见[待定事项](待定.md)。

## 版本号

版本号形式、归一化规则、发行语言集、产物命名与校验和、tag 规则统一见
[发行规范](发行规范.md)；本节只给最常用的命令。

首个正式版 `v1.0.0`，未完成干净 GOG 副本验收时用 `v0.9.0`。

打 tag 前重新生成，并创建/推送 tag（tag 为 annotated，且要求工作树干净）：

```powershell
.\release.ps1 -Version v1.0.0 -Tag -Push
```

只想先在本地出包、暂不推 tag：

```powershell
.\release.ps1 -Version v1.0.0
```

## 目标

**一个 zip 同时面向 GOG 和 Steam**：玩家不分入口，下载自己语言的包，解压到游戏目录即可。包内的**进游戏入口也是同一个**：双击 `PR2LocalizationGUI.exe` 选语言启动。启动器自己判断版别——GOG 走注入，Steam 先确保宿主 DLL 代理就位再直启 `PR2.exe`。Steam 版的还原也在这一个入口上：GUI 的「还原 Steam 原版」按钮，或 `PR2Localization.exe --restore`。

```
PR2-zh-v1.0.0.zip
├─ PR2Localization.exe
├─ PR2LocalizationGUI.exe      ← 图形界面入口：选语言启动（两版共用）
├─ PR2LocalizationCore.dll
├─ PR2HostMount.ps1            ← 校验、备份、挂载、还原（启动器和 GUI 都调它；GOG 不执行）
├─ PR2Localization/
│  ├─ host/
│  │  └─ Ascaron.Logging-2.6.dll ← Steam 宿主代理，挂载时才换进根目录
│  ├─ packs/
│  │  ├─ zh.txt
│  │  └─ locale.default.ini   ← 默认语言；用户 locale.ini 优先，包内不放活动文件
│  ├─ fonts/
│  │  ├─ font-map.default.ini
│  │  ├─ NotoSansSC-Regular.ttf
│  │  ├─ NotoSerifSC-Black.ttf
│  │  └─ NotoSerifSC-Bold.ttf
│  ├─ ui/
│  │  └─ ui.default.ini      ← 固定界面文案；用户 ui.ini 按项覆盖
│  └─ logs/                 ← 运行时生成
├─ README.txt
├─ NOTO-SOURCES.txt       ← 字体来源说明（不放进 fonts/）
├─ RUNTIME-VERSION        ← 运行时版本，用于语言包兼容检查
├─ manifest.json          ← 发布清单：两个目标 exe、来源、逐文件 SHA-256
└─ OFL.txt
```

包里**不包含 `VERSION.dll`**：GOG 的 `PR2.exe` 不加载同目录代理，Steam 已改用宿主 DLL，
这个文件两条路线都不再需要。

宿主代理与脚本只在 Steam 侧起作用：判版按游戏目录的标记文件走，GOG 目录里这两项从不被读取，
所以同一个包不需要为 GOG 单独裁掉它们。

代理**不**以根目录同名文件的形式发行：解压到游戏目录时不会覆盖原版
`Ascaron.Logging-2.6.dll`，挂载动作由启动器在启动前完成。玩家从没挂载过也能直接启动，
第一次启动时才生成 `.orig.dll` 和 `host-backup`。

Steam 的挂载脚本只替换 `Ascaron.Logging-2.6.dll`。它会校验原版的 `11,776 B` 和
SHA-256 `0568EC654E147B6D80F60B779843F020A9C8A7C4E53AE0BC364EC6937024D160`；
通过后备份为 `Ascaron.Logging-2.6.orig.dll` 和
`PR2Localization\host-backup\Ascaron.Logging-2.6.dll`，再换代理。大小或哈希不对时
停止，不覆盖未知文件。

替换本身是**原子**的：代理先复制成 `Ascaron.Logging-2.6.dll.new`，校验哈希通过后
才换名覆盖正式文件。复制中途被游戏或杀毒占用而失败时，根目录留下的仍是原来那份
DLL，不会出现半截文件；还原用的是同一套动作，`Ascaron.Logging-2.6.orig.dll`
同样先校验再换名。

### 发布清单 `manifest.json`

每个 zip 根目录带一份 `manifest.json`，由 `src/tools/pack/release_manifest.py`
在打包前生成并立即校验。字段：

| 字段 | 内容 |
|---|---|
| `schema` | 清单格式版本，当前为 `2`（`target` 单值改为 `targets` 列表） |
| `package_id` | 发行包目录名，如 `PR2-zh-v1.0.0`、`PR2-latin-v1.0.0` |
| `lang` | 默认语言（合包取分组 `default`） |
| `langs` | 包内全部语言；单语言包就一个元素 |
| `edition` / `version` | 固定 `universal`（一个包同时面向两版）、版本 |
| `runtime_version` | 与根目录 `RUNTIME-VERSION` 一致 |
| `font_mode` | `noto` / `config` / `none` |
| `build` | 构建审计信息：`at`（UTC ISO8601）、`commit`（短 SHA，取不到为 `null`）、`dirty`（工作树有未提交改动为 `true`） |
| `targets` | 两个已知构建（`gog-en-1.1.2.3`、`steam-en-1.1.2.3`），各含 `edition`、版本 id、说明、`PR2.exe` 的 SHA-256 |
| `translation` | 默认语言的译文标记（`tags`：fan/community/ai-assist 等）、审阅状态（`review_status`）、参考语言（`source_lang`） |
| `translations` | 包内每门语言一条，字段同上，顺序与 `langs` 一致 |
| `source` | `src/orig/<source_lang>.toml` 相对路径和 SHA-256 |
| `files` | 包内每个文件的相对路径、类别、大小、SHA-256；不含 `manifest.json` 自身 |
| `counts` | 文件数和总字节数 |

构建时 `make_release.py` 写完清单后调用 `verify_release_manifest()`：文件缺失、大小或
SHA-256 不一致、清单外多出文件、路径越界都会让本次出包失败。清单只用于审计和 CI，
运行时仍只读语言包、`locale.ini` 和字体映射，不依赖这份 JSON。

`translation` 的内容来自 `src/packs/<语言>.toml`：

```toml
tags = ["fan", "community", "ai-assist"]  # 必填，词表见 src/tools/pack/pack_tags.py
review_status = "preview"                 # 完成度：preview / complete
source_lang = "en.gog_1.1.2.3"
```

`tags` 描述“谁做的、怎么做的”：`fan`（同人，非官方）、`community`（社区协作）、
`ai-assist`（AI 辅助、有人工审校）、`machine`（纯机翻未校对）、`official` / `retail`
（官方或零售版附带）。我们自己的译文统一是 fan + community + ai-assist。
这行标记同时写进包根 `README.txt` 第 3 行（“标记：同人制作 · 社区协作 · AI 辅助；审阅：预览版”）。

这些字段只进清单，不写进语言包 `# pack-meta`，也不改变语言包契约；`compile_pack.py`
仍只复制 `alias`、`min_runtime`，所以游戏内 GUI 不显示标记，玩家看到的是 `README.txt`。
缺 `tags` 时 `config_check.py` 直接报错，不会出一个没有标记的包。

`PR2Localization/fonts/` 放实际字体文件（默认保留 Noto 原始文件名）和
`font-map.default.ini`，不按语言单开子目录，也不放说明文件；游戏会扫描这个目录。
四个游戏逻辑名由默认映射指向这些实际文件，两个逻辑名可指向同一文件。
要自定义时新建或编辑同目录的 `font-map.ini`，只写需要覆盖的逻辑名；运行时以默认文件
为基础按项叠加用户项；发行包不含这个文件名，因此解压升级不会覆盖手工配置。四个逻辑名全部写 `none` 表示不重定向、直接用根目录原版字体；同一次安装只放一个语言的字体。字体来源说明统一放在包根 `NOTO-SOURCES.txt`。

正式入口两版共用：双击 `PR2LocalizationGUI.exe` → 列表里选语言 → 「以所选语言启动」；
「启动原版」直接进英文。GOG 侧由启动器注入，Steam 侧见下一段。
GOG 不要直接双击 `PR2.exe`：加载器会把 `VERSION.dll`
解析到 `C:\Windows\SysWOW64\VERSION.dll`，同目录代理不会进入游戏进程。
GUI 只是调用 `PR2Localization.exe --lang=…`，由它注入 `PR2LocalizationCore.dll`；
DLL 通过路径重定向让游戏读取 `PR2Localization/fonts/`，不覆盖根目录原版字体。
DLL 会按 `locale.ini`（没有活动文件时按 `locale.default.ini`）选择语言，并以
`font-map.default.ini` 为基础、用 `font-map.ini` 按项覆盖后选择具体字体文件。活动 `locale.ini` 存在但
`language=` 为空时也会保留这个空值，不自动回退默认语言；但运行时空值不等于原版英文，
DLL 仍会以内置 `zh` 兜底。原版入口是 `PR2Localization.exe --vanilla` 或 GUI「启动原版」。
发行包不含活动 `locale.ini`，解压升级不会覆盖玩家已选语言；`packs\overrides\` 是用户本机覆盖，
部署/升级不会删除。

Steam 版：同样是双击 GUI。启动器判出 Steam 版后，先看根目录的宿主 DLL 是原版还是已挂载的
代理——原版就调 `PR2HostMount.ps1 -Action Mount` 校验、备份、换名挂载，已挂载就跳过，
然后不经 Steam 客户端、直接启动 `PR2.exe`。代理由 `PR2.exe` 静态导入的
`Ascaron.Logging-2.6.dll` 加载，并加载同目录 `PR2LocalizationCore.dll`。
还原点 GUI 的「还原 Steam 原版」，或跑 `PR2Localization.exe --restore`，两者都落到同一脚本的
`-Action Restore`（先把原版写进 `.new` 校验，再换名回填）。
宿主动作的每一步都写进 `PR2Localization/logs/host.log`：GUI 用 `CREATE_NO_WINDOW` 调起
启动器，看不到控制台，还原失败时对话框里显示的就是这份日志的末尾几行。
GUI 界面为单列分层布局，按系统 DPI 缩放；语言包、启动、还原和结束进程的按钮分组显示。
如果游戏退出时卡死，点「结束游戏进程」：它只结束本目录启动的 `PR2.exe`，
会先弹确认，不会误杀 Steam 或其他目录的游戏副本。

语言包只带显示名和最低运行时版本：

```toml
# src/packs/zh.toml
alias = "简体中文"
min_runtime = 1
```

编译后写进语言包开头：

```
# pack-meta alias=简体中文
# pack-meta min_runtime=1
```

游戏会忽略 `#` 注释；GUI 读取它们后只在列表显示 `alias`，不再根据语言包切换界面语言。
启动器界面固定读 `PR2Localization/ui/ui.default.ini`；用户要改文案时，在同目录放
`ui.ini`，只写要覆盖的 key。发行包只带 `ui.default.ini`，所以解压升级不会覆盖用户文件。

没有 `# pack-meta` 的语言包，列表直接显示语言代码；不再支持外部别名覆盖。

GUI 启动成功后会直接把所选语言写回活动配置：

```ini
# PR2Localization/packs/locale.ini
language=zh
```

发行包只带 `PR2Localization/packs/locale.default.ini`；已有 `locale.ini` 时 GUI 和运行时都以它为准。
下次打开启动器会默认选它；GOG 仍从 `PR2LocalizationGUI.exe` 进入，不要直接双击 `PR2.exe`。

显示名只来自语言包 `# pack-meta alias`；启动器界面固定使用默认 `ui.default.ini`，
不再跟随语言包或 Windows UI 语言。

语言包可以声明最低运行时版本：

```
# pack-meta min_runtime=1
```

`min_runtime` 高于当前运行时版本时，GUI/启动器会拒绝启动并提示更新，
避免“旧 DLL + 新语言包”静默不翻译。

不包含游戏本体、`.cpr`、地图、音乐等游戏资源。

## 字体

发行版只做映射，直接把完整 Noto 字体以原始文件名放进 `fonts`：

| 游戏逻辑名 | 映射到的实际文件 |
|---|---|
| `ARIAL.TTF` | `NotoSansSC-Regular.ttf` / `NotoSansJP-Regular.ttf` |
| `ELGRECO_.TTF` | `NotoSerifSC-Black.ttf` / `NotoSerifJP-Black.ttf` |
| `Tiepolo_black.ttf` | `NotoSerifSC-Black.ttf` / `NotoSerifJP-Black.ttf` |
| `Tiepolo_bold.ttf` | `NotoSerifSC-Bold.ttf` / `NotoSerifJP-Bold.ttf` |

- **不裁剪**：保留完整字符集；
- VF 会实例化成静态字重；
- 字体使用 SIL OFL 1.1，发行包附 `OFL.txt`；
- 获取渠道：
  - Google Fonts：Noto Sans SC / Noto Serif SC / Noto Sans JP / Noto Serif JP
  - <https://fonts.google.com/noto>
  - <https://openfontlicense.org/>

字体较大（中文一套约 50 MB，zip 约 32 MB）。这是“不裁剪”的代价。

包内保留实际 Noto 文件名，**不再把文件改名为 `ARIAL.TTF` 等游戏逻辑名**；
`ELGRECO_.TTF` 和 `Tiepolo_black.ttf` 可以映射到同一个
`NotoSerifSC-Black.ttf`，因此默认包是 3 个实际 TTF 加 1 个 `font-map.default.ini`。

如果本机已经有静态的 `NotoSansSC-Regular`、`NotoSerifSC-Bold`、`NotoSerifSC-Black`
等文件，生成过程只是复制，**不需要 fontTools**。只有源文件是
`*-VF.ttf` 可变字体时，才需要 fontTools 把它实例化成静态字重。

默认 `--fonts noto` 在 `PR2Localization\fonts\` 平铺这些实际字体文件，
并附带 `font-map.default.ini`；映射缺失或文件不存在时回退根目录原版。

`--fonts config` 只把 `src/font-map.ini` 复制为
`PR2Localization\fonts\font-map.default.ini`，不携带 TTF。映射值只接受
`PR2Localization\fonts\` 内的实际文件名，不读 `%WINDIR%\Fonts`；使用这种包
必须自己把映射中写明的字体文件放进 `fonts`，否则 GUI 会提示字体缺失。
用户自定义时写同目录的 `font-map.ini`，只写要覆盖的项；它按项覆盖默认文件，
解压升级不会覆盖它。

### 字体缓存

生成结果缓存在：

```
build/cache/noto/
```

缓存键包含源字体内容 SHA-256、字重、目标文件名、fontTools 版本和缓存版本：
源字体或参数变化才会重算。第二次打包同一语言会直接用缓存。

强制重算：

```powershell
python src\tools\font\make_noto_fonts.py --lang zh --out <目录> --no-cache
```

换缓存目录：

```powershell
python src\tools\font\make_noto_fonts.py --lang zh --out <目录> --cache-dir D:\font-cache
```

`make_release.py` 默认复用缓存；强制重算：

```powershell
python src\tools\pack\make_release.py --lang zh --version v1.0.0
python src\tools\pack\make_release.py --lang zh --version v1.0.0 --no-font-cache
```

## 字体缺失时

### 程序怎么判断

本地化启动时检查：

```
<游戏目录>\PR2Localization\fonts\
├─ font-map.default.ini
├─ NotoSansSC-Regular.ttf
├─ NotoSerifSC-Black.ttf
└─ NotoSerifSC-Bold.ttf
```

启动器检查的是当前映射（默认文件为基础，`font-map.ini` 存在时按项覆盖）
的四个逻辑名是否都能映射到 `fonts` 内真实存在的文件；
四个缺任意一个，就算“字体不完整”。两个逻辑名可以指向同一个实际文件。

### 程序怎么处理

**GUI（`PR2LocalizationGUI.exe`）**

弹窗：

> `PR2Localization\fonts\ 缺少字体 TTF。仍然启动会使用原版拉丁字体，中文可能缺字。仍要启动吗？`

- 选“是”：继续启动；
- 选“否”：取消。

**启动器（`PR2Localization.exe`）**

即使绕过 GUI，也会再次检查：

- 字体完整：设置 `PR2_FONT_DIR=<语言>`，重定向到 `PR2Localization\fonts\`；
- 字体不完整：不设置重定向，回退到 `fonts\` 根目录的原版字体，并在控制台打印：

```
[PR2Loc] PR2Localization\fonts 字体不完整，回退到原版根目录字体
```

这时游戏能启动，但中文很可能显示空白；只有原版拉丁字符正常。

### 用户应该怎么处理

1. **检查目录和映射**
   确认游戏目录下确实有：

   ```
   PR2Localization\fonts\font-map.default.ini
   PR2Localization\fonts\NotoSansSC-Regular.ttf
   PR2Localization\fonts\NotoSerifSC-Black.ttf
   PR2Localization\fonts\NotoSerifSC-Bold.ttf
   ```

   并确认当前映射（默认文件为基础，`font-map.ini` 存在时按项覆盖）的四个逻辑名指向上面的实际文件。

2. **重新解压字体**
   从发行 zip 里解压 `PR2Localization\fonts\` 整个目录；只复制语言包
   `PR2Localization\packs\<语言>.txt` 是不够的。

3. **不要放到根目录**
   原版字体留在 `fonts\` 根目录，本地化字体必须放
   `PR2Localization\fonts\`，实际字体文件和 `font-map.default.ini` 平铺，不建语言子目录。

4. **检查杀毒软件**
   字体文件较大，偶尔会被隔离；恢复后重新启动。

5. **确认语言代码一致**
   `PR2Localization\packs\<语言>.txt`、`PR2Localization\fonts\`、`locale.ini`（或
   `locale.default.ini`）的 `language=` 必须是同一个代码（如都是 `zh`）。

6. **仍要启动**
   可以选择继续，但只能看到原版拉丁字体；中文缺失不是游戏坏了。

### 原版字体

原版四个 TTF 留在 `fonts\` 根目录，不会被本地化覆盖。
启动器第一次替换前还会备份到 `PR2Localization\fonts\_original\`（SHA-256 校验）；
`PR2Localization.exe --vanilla` 使用根目录原版。

## 生成

### 1. 一键出包

需要 Rust（rustup）、`i686-pc-windows-msvc` target、Python 3.11+ 和 PowerShell 7：

```powershell
rustup target add i686-pc-windows-msvc
Set-Location <仓库目录>
.\release.ps1 -Version v1.0.0
```

默认流程：

1. 先跑 `src/tools/config_check.py` 检查 locale/packs/translations/ui/font-map 的语言配置，失败则拒绝出包；
2. 调 `build.ps1 -Target Injector` 构建运行时；
3. 读 `src\release-bundles.toml` 取发行分组（分组里的语言必须都在 `src\release-languages.txt` 里），
   并核对每门语言的 pack / 译文 / 字体映射三件齐全
   （有 `-Lang` 时以命令行为准，但同样要过这三件检查）；
4. 对每个分组各调一次 `make_release.py --bundle <id>`，
   把组内语言编进同一个 `packs\` 目录、共用一份 `font-map.default.ini` 与一处 `fonts\`，
   组装一个 zip（同时带宿主代理与挂载脚本，两版通用），打包后删除 stage 目录；
5. 写 `dist\SHA256SUMS.txt`。

输出（5 个分组，每组一个 zip；`latin` 一个包里是 `de` / `es` / `fr` / `it` 四门）：

```
dist\PR2-zh-v1.0.0.zip
dist\PR2-ja-v1.0.0.zip
dist\PR2-ko-v1.0.0.zip
dist\PR2-ru-v1.0.0.zip
dist\PR2-latin-v1.0.0.zip
dist\SHA256SUMS.txt
```

合包的判据是**字体能不能共用**：`de` / `es` / `fr` / `it` 在 `font-map.ini` 里四项映射全是 `none`，
原来四份 zip 各自只带一份映射、零字体，合成 `latin` 后仍然零字体，体积从 4 × ~0.5 MB 变成 1 × 0.85 MB。
`zh` / `ja` / `ko` / `ru` 各带一套文件名不同的字体，合成一包不会省体积，所以保持一语言一包。

只打一个分组：

```powershell
.\release.ps1 -Version v1.0.0 -Bundle latin
```

只打一个语言（旧口径，一语言一包）：

```powershell
.\release.ps1 -Version v1.0.0 -Lang zh
```

一个包同时面向两版，不再按入口出两份，所以没有「只打 GOG / 只打 Steam」的口径。

已经有 `build\runtime` 时，跳过注入器：

```powershell
.\release.ps1 -Version v1.0.0 -SkipInjector
```

默认 `-Fonts auto`：按 `src\font-map.ini` 的 `[<lang>]` 四项映射自动决定每门语言的模式，
四项全是 `none` 的走 `config`，其余走 `noto`。因此一次调用可以混合多门语言：
`de` / `es` / `fr` / `it` 出“只带映射”的小包，`zh` / `ja` / `ko` / `ru` 出带字体的包。

只做本地流程测试、不想生成大字体包时：

```powershell
.\release.ps1 -Version v0.0.0-test -Fonts none -SkipInjector
```

强制全部只带映射、不打包字体：

```powershell
.\release.ps1 -Version v0.0.0-config -Fonts config -SkipInjector
```

`-Fonts config` 不复制任何 TTF，只把 `src\font-map.ini` 复制为
`PR2Localization\fonts\font-map.default.ini`。映射值只接受 `PR2Localization\fonts\`
内的实际文件名；使用这种包时必须自己把映射中写明的字体文件放进 `fonts`，
否则 GUI 会提示字体缺失。

`-Fonts noto` 把实际字体平铺进 `PR2Localization\fonts\`（`zh` / `ja` / `ko` 是三个
Noto 静态字重，`ru` 是自建的四个度量对齐字体），同时附带 `font-map.default.ini`；
用户自定义写 `font-map.ini`，只写要覆盖的项，运行时按项叠加。

`make_release.py` 会自动：

- 编译语言包；
- 按 `--fonts`（默认 `auto`）决定每门语言的字体模式：`auto` / `noto` 生成字体，
  `config` / `none` 不生成字体；
- 复制运行时、`PR2Localization/ui/`、`PR2Localization/packs/` 和字体/字体映射；
- 恒定把代理复制到 `PR2Localization/host/Ascaron.Logging-2.6.dll`（不进根目录），
  并复制 `PR2HostMount.ps1`：两版共用一个包，GOG 侧不执行这两项；
- 写入 `RUNTIME-VERSION` 和支持版本说明；
- 打包 `README.txt`；`--fonts noto` 时附带 `OFL.txt`。

第一次生成 VF 静态字重需要：

```powershell
python -m pip install fonttools
```

字体结果缓存在 `build\cache\noto\`，之后打包会直接复用。
强制重算：

```powershell
.\release.ps1 -Version v1.0.0 -NoFontCache
```

低层排障时仍可直接调用：

```powershell
python src\tools\pack\make_release.py --lang zh --version v1.0.0
```

### 3. 打包方式

当前是**一个分组一个 bundle，同时面向两版**（运行时 + 宿主代理 + 挂载脚本 + 语言包 + 字体在一个 zip 里）。
两种游戏都用同一个入口 `PR2LocalizationGUI.exe`；包里的代理
放在 `PR2Localization\host\`，由启动器在启动前校验、备份、换名挂载，玩家不用先跑脚本，也不用
从 Steam 客户端启动。GOG 目录里判版结果是 GOG，代理和脚本从不被读取。

Runtime + Language 拆分包保留为以后方案，暂不启用；等语言数量明显增加或
运行时需要频繁单独更新时再评估。

### 4. 发版前验证

1. 解压到干净的游戏副本；
2. 两版都双击 `PR2LocalizationGUI.exe`，选语言后「以所选语言启动」：GOG 应打印注入成功，
   Steam 应先打印挂载（或跳过挂载）再启动，根目录 DLL 变成代理大小；
3. 检查 `PR2Localization\logs\runtime.log` 首行有 `pack '<语言>' ... overrides`；
   Steam 再检查 `PR2Localization\logs\host.log` 有挂载记录；
4. 再用 `PR2Localization.exe --lang=<语言>` 直接启动，检查命令行入口；
5. Steam 点 GUI「还原 Steam 原版」（或 `--restore`），确认根目录 DLL 回到 11,776 B、
   `host-mount.json` 消失；再点一次应提示「已经是原版，不需要还原」；
6. 检查界面文本、字体、原版启动；
7. 确认 `README.txt` 支持版本是 **GOG 英文 1.1.2.3 已实测 / Steam 英文 1.1.2.3 已实测（宿主 DLL）**。

只生成字体、不编语言包：

```powershell
python src\tools\font\make_noto_fonts.py --lang zh --out build\runtime\PR2Localization\fonts
```

### 其他语言

在 `src/tools/font/make_noto_fonts.py` 的 `LANGS` 里加映射，例如：

```python
"ko": {
    "sans": ("NotoSansKR", 400),
    "serif": ("NotoSerifKR", (700, 900)),
    "label": "Korean",
},
```

字体命名规则需与本机安装一致；没有对应 Noto 字体时先在 Google Fonts 下载安装。

## 进阶：字体调整

字体只做映射，不走“原版字体 + donor 缝合”。需要调字形时，
`src/tools/font/squeeze_fonts.py` 按原版度量横向压缩字形，产物仍是普通静态 TTF，
由 `font-map.ini` 映射即可；没有缝合缓存、没有 presets，也没有 `--fonts stitch`。

## GitHub Actions

仓库有两个工作流：

- `.github/workflows/ci.yml`：`dev` / `main` 的 push、Pull Request 和手动触发。
  跑 `.\check.ps1`，再用 `.\build.ps1 -Target All` 编译 Rust、宿主代理和全部语言包。
- `.github/workflows/release.yml`：`release-v*` tag 或手动触发。
  手动触发只上传 workflow artifact；tag 触发会额外发布 GitHub Release。

Release 工作流在 `windows-latest` 上执行，依赖：

- Python 3.12 + `fonttools`；
- Rust stable + `i686-pc-windows-msvc`；
- MSVC 链接器 / Windows SDK（Rust `i686-pc-windows-msvc` target 需要；项目不含 C++ 源码）；
- Google Fonts 的 Noto Sans/Serif SC/JP/KR 可变字体，下载到
  `%LOCALAPPDATA%\Microsoft\Windows\Fonts`，由 `make_noto_fonts.py` 实例化成静态字重；
  本机没有时也可把静态 TTF 放进 `build\cache\noto-src\`（脚本会先找静态字重，再退回 VF）。

核心出包命令（分组来自 `src/release-bundles.toml`，不再硬编码）：

```powershell
$bundles = $env:BUNDLES -split ','   # CI 里由 make_release.py --list-bundles 解析而来
.\release.ps1 -Version $env:VERSION -Bundle $bundles -NoPause
```

以当前分组为例，一次生成五个包加校验和（`zh` / `ja` / `ko` / `ru` 各一，
`latin` 一个内含 `de`+`es`+`fr`+`it`）：

```text
dist/PR2-{zh,ja,ko,ru,latin}-$env:VERSION.zip
dist/SHA256SUMS.txt
```

CI 里设置 `SOURCE_DATE_EPOCH` 为 tag 对应提交时间后，重建出的包与本地逐字节一致。

每个包都带 `PR2HostMount.ps1` 与 `PR2Localization/host/Ascaron.Logging-2.6.dll`，
根目录没有同名 DLL，也都不带 `VERSION.dll`。`tests/test_release_layout.py` 守着这条布局，
`tests/test_host_constants.py` 守着 Rust / Python / PowerShell 三处的 11,776 B 与 SHA-256。
`release.ps1` 已会先构建注入器，CI 不再单独调用
`src\build_injector.ps1`，也不需要重复传 `-SkipInjector`。

手动验证发版流程：在 Actions 页运行 `Release`，填写 `v1.0.0` 之类的版本号；
不创建 tag，不会发布 GitHub Release，只保留构建 artifact（含 `SHA256SUMS.txt`）。
要正式发布时创建并推送 `release-v1.0.0` tag。
