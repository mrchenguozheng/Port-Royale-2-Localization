# 德语校对流程（可复用的机械层）

本文件说明德语译文现在怎么校、用什么跑、哪些规则已经自动化、哪些仍然只能人工判断。

## 1. 三层校验，各管一段

| 层 | 工具 | 查什么 | 假阳性特征 |
|---|---|---|---|
| 确定性层 | `src/tools/analysis/de_lint.py` | 占位/标记丢失、敬称命令式、禁用变体、状态动词、叠词、引号、句末标点、句首大小写 | 极少；命中即需处理，个别保留项在文末列出 |
| 对照层 | `src/tools/analysis/de_crosscheck.py` | 跨语言相似度、术语偏离、否定、标点计数、专名保留 | 多；结论须逐条判读，判读结果写 `docs/德语交叉核对.md` |
| 编译层 | `compile_pack.py --strict` | 条目数、占位未翻译、包结构 | 只认结构，不认语感 |

三层缺一不可：lint 抓硬错，crosscheck 抓"和另三种语言不一致的地方"，编译层保证包能用。

## 2. 命令

```
python src/tools/analysis/de_lint.py --json build/qa/de_lint.json --md docs/德语校对清单.md
python src/tools/analysis/de_crosscheck.py --json build/qa/de_crosscheck.json --md docs/德语交叉核对.md
python src/tools/pack/compile_pack.py --lang de --out build/runtime/PR2Localization/packs --strict --no-fonts
python src/tools/config_check.py
```

`de_lint.py` 有 E 级命中时退出码为 1，可以直接串进提交前检查；`de_crosscheck.py --only E1,E4` 可只看某几类。

## 3. `de_lint.py` 的规则表

| 代码 | 级别 | 内容 |
|---|---|---|
| L0 | E | 基准有、译文缺条 |
| L1 | E | `@X$…$`/`%1` 占位集合不一致；`<ts:>`、`<f:fonts/>`、`<gs:>`、`<g:>`、`<c>`、`<n>`、`<t>` 个数不一致 |
| L2 | E/W | 句首 du-命令式（表内应 Ihr 敬称）；引号外的 `du/dich/dir/dein` |
| L3 | E | 禁用/不一致变体（`Türkeninseln`、`Blühende Wirtschaft`、`Kraweel`、`Anheuerung` 等） |
| L4 | E | `Status fällt/gefallen/fiel`（八档口径定 `sinkt`） |
| L5 | W | 名词化与官僚腔 token：`zur Verfügung`、`verfügt über`、`verstrickt`、`besteht darin`、`Euer (nächstes|erstes) Ziel ist es`、`gewährleisten`、`erfolgt`、`harren` |
| L6 | E/W | 引号 `„ “` 不配对（E）；连续空格、标签前空格、段末缺标点（W，且只在英文该处有时才报） |
| L7 | W | 句首小写：按 `<n>` 分段比对英文首字母；排除书信称呼（上一段以逗号结尾）与罗马数字、常见缩写 |
| L8 | E | 硬叠词（`und und`、`ist ist`、`nicht nicht` 等）；冠词相邻（`die, die …`）属正常德语，不报 |

已知保留项（每次跑都会剩这 2 条，判读后不动）：

- `0x1ca50773` 的 `sie besteht darin, …` —— 这里就是"任务内容是……"，改写反而生硬。
- `0xfb343dde` 的段末 `!“` —— 英文在引号后还多一个 `.`，德语按规范不补。

## 4. 句式模板库（改写时先套模板）

| 英文句式 | 不要写 | 写成 |
|---|---|---|
| `Your (next|first) objective is to …` / `Your task is to …` | `Euer Ziel ist es, … zu …`；`Das Ziel besteht darin, … zu …` | `Als Nächstes sollt Ihr …` / `Zuerst sollt Ihr …` |
| `You have been assigned the mission of …` | `Ihr habt den Auftrag erhalten, … zu …` | 保留（已定稿）或 `Man hat Euch beauftragt, …` |
| `X has provided you with Y` / `… available to you` | `X hat Euch Y zur Verfügung gestellt` | `X hat Euch Y geschenkt` / `Y ist für Euch freigegeben` |
| `You have @g$X$ cash available` | `Euch stehen @g$X$ zur Verfügung` | `Ihr habt @g$X$ dabei` |
| `By trading, donating, organizing …` | `durch Handel, Spenden, das Ausrichten von …` | `indem Ihr handelt, spendet, … ausrichtet` |
| `It is advisable to …` | `Es ist ratsam` | `Am besten …` |
| `involved in the war` | `in den Krieg verstrickt` | `im Krieg` |
| `The town's status falls` | `Status fällt` | `Status sinkt` |
| `capture a town` | `annektieren`（零售口径） | `erobern`（原文 `annexed` 才用 `annektieren`） |
| `crew` | `Besatzung`（仅 UI 数值栏） | `Mannschaft`（叙事与教程） |
| `business` | `Gewerbe` | `Betrieb` |

## 5. 批量写入的两种方式

**A. FRAG 三元组（改少量句子，最省 token）**

```python
FRAG = [
    ("0xKEY", "旧串", "新串"),   # 旧串必须唯一且存在
]
```

先 `assert a in old[k]` 断言旧串存在；逐行按 key 定位替换；写完用 `tomllib` 读回，比较键集合与改前一致。

**B. 补丁 JSON（整条重写，`de_apply.py`）**

```json
{"0xKEY": "整条新译文"}
```

`de_apply.py` 会断言键存在、占位集合与英文一致，按 TOML 双引号规则整行写回，并读回校验键集合。

两种方式都不改文件头尾与其它键；`Set-Content`/`Out-File` 会改行尾，一律用 Python `io.open(..., newline="\n")`。

## 6. 一次改动的典型循环

1. `de_lint.py` → 有 E 就先清 E（硬错优先）。
2. 取本批条目：`tomllib` 读 `src/orig/en.gog_1.1.2.3.toml` 与 `src/translations/de.toml`，需要歧义裁断时加 `fr.gog_1.1.2.42.toml`、`de.retail-1.0.0.toml`。
3. 套第 4 节模板改写，按第 5 节写入。
4. `de_lint.py` 再跑一遍，确认没引入新 E。
5. `compile_pack --strict`（应始终 3548 条、占位未翻译 0）。
6. `config_check`，然后 `deploy(langs=["ru","de"], edition="gog")` 部署到游戏目录。
7. 提交。提交信息用 `git commit -F build/qa/de_commit_msg.txt`，消息先写文件再提交。

## 7. 明确不做的事

- 不用像素或字体宽度做排版判据（控件宽度未实测）。
- 不把零售德语当底稿，只当句式与术语的佐证；零售缺条、且有 42 条不在本版本基准表里。
- 不把未实机验证的结论写成"已修复"；本轮所有结论都来自静态校验与 en／fr／de-retail 三语比对。
