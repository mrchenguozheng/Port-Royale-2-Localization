# 中文长文本分词加空格 —— 方案（待确认）

> 目标：让引擎能在一句话内部的**词边界**换行，避免「一长串汉字被整行裁切/丢弃」。
> 只影响中文（`zh.toml`），日语走自己的助词空格规则。

## 一、现状（`zh.toml` 3,548 条）

| 指标 | 数值 |
|---|---|
| 含汉字的条目 | 3,304 |
| 已经加过空格的条目 | **842**（提交 `c347720`，spaCy 分词） |
| 最宽 token ≥ 300px | 27 |
| 最宽 token ≥ 250px | 71 |
| 最宽 token ≥ 180px | **272** |
| 最宽 token ≥ 150px | 558 |
| 最宽 token ≥ 120px | **1,025** |
| 最宽 token 中位数 / 90% 分位 / 最大 | 84px / 168px / 504px |

在 14px 字体下，一个汉字约 14px，所以 **120px ≈ 8.5 个汉字**，
180px ≈ 13 个汉字。

## 二、已定位的问题（这就是 272 条还没处理的原因）

1. **人名保护正则太贪心**：`[\u4e00-\u9fff]+(?:·[\u4e00-\u9fff]+)+`
   会把「马丁·瓦尔德泽米勒要为这些未知土地想出一个名字时」整段当成人名，
   于是整句被跳过、一个字都没加空格。
   实测 `0xd4cd1020` 的这条：504px，加空格后仍是 504px——因为它被整段保护了。
2. **阈值只覆盖最长的那些**：当时条件是「汉字串 ≥12 且 token ≥180px」，
   于是 120–180px 之间的 753 条（1,025 − 272）完全没动。
3. **历史文/百科类条目**（`0xd4cd10xx` 一片）恰好都带人名，几乎全军覆没。

## 三、三个方案

### 方案 A：只补漏（最小改动）

修正则 → 用**原阈值**重跑。预计新增约 200 条，总覆盖 ~1,040 条。
优点：改动小、风险低；缺点：120–180px 的中长句仍然可能裁切。

### 方案 B（推荐）：v2 算法 + 120px 阈值

- **不再先按人名切**：把整段（去掉标签后）交给 spaCy 分词，人名（含 `·`）、
  数字、单位、标签、占位符都当作**原子 token**，不拆；
- 只在「两个词之间」加空格，标点两侧不加；
- 按目标宽度 **120px** 成组，组间才加空格；
- 预计覆盖 **1,025 条**（含已处理的 842 条里会重排的那些），
  让最常见的控件宽度（约 8–10 个汉字）都能换行。

### 方案 C：全量

凡含汉字且长度 ≥8 的条目都加空格（约 1,264 条），最激进，
中文会读起来像朝鲜语（词间全空格），视觉最碎，不推荐。

## 四、质量规则（三案共用）

| 规则 | 做法 |
|---|---|
| 标签 / 占位符 | 先替换成占位符，处理完再还原；逐条校验序列完全一致 |
| 标点 | `，。！？、：；）」』】` 两侧不加空格；已有「标点后空格」保留 |
| 数字 / 单位 / 百分比 | `60 トン`、`%1`、`(60 tons)` 不拆 |
| 人名 | 含 `·` 的整段原子化（用 v2 的 token 边界，不靠正则猜） |
| 单字虚词 | 的/了/是/在/和… 粘在前一个词后，避免「你 的 目标」 |
| 术语 | 继续用 `zh_userdict.txt`（私掠者、总督城…） |

## 五、流程怎么接

1. `space_words.py` 增加 `--mode v2`（新算法），旧的 `v1` 保留对照；
2. `apply_patch.py` 增加可选步骤 `--space`：编译前先跑一次 v2（**幂等**，
   已加过空格的不再重复加）；
3. 每次运行输出 `docs/space-words-zh.csv`：`hash / before_px / after_px /
   spaces / zh / new`，供抽查。

## 六、验收标准

- `check_breaks` 0 条不一致；标签序列 100% 一致；
- `docs/space-words-zh.csv` 里没有「after ≥ before」的条目；
- 最宽 token 的 90% 分位从 168px 降到 **≤130px**；
- 抽查 20 条历史文（`0xd4cd10xx`）读一遍，确认没有把词拆坏；
- 实机看 3 个界面：港口主界面、剧本选择、百科/历史条目。

## 七、风险与回退

| 风险 | 处理 |
|---|---|
| 空格变多 → 行数增加，可能竖向溢出 | 目标宽度 120px，只在超宽时加；实机看长文本面板 |
| 名字被拆（瓦尔德 / 泽米勒） | v2 原子化避免；抽查名字条目 |
| 需要回退 | 每次是一个独立提交，`git revert` 即可；包重新 `apply_patch` 部署 |

## 八、需要你确认

1. **选哪个方案**：A（补漏）/ **B（推荐，120px）** / C（全量）？
2. **目标宽度**：120px（约 8.5 字）还是更保守的 100px（约 7 字）？
3. **要不要并进 `apply_patch.bat`**：每次部署自动加空格（幂等），
   还是保留成手动命令？
