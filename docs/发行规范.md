# 发行规范

适用于本仓库对外发布的 zip。规范只写“必须是”，实现落在 `release.ps1`、
`src/tools/pack/make_release.py` 和 `.github/workflows/release.yml`；包内的目录结构、
字体策略见[发行版](发行版.md)。

## 1. 版本号

- 形式：`vMAJOR.MINOR.PATCH`，可带预发布后缀 `-prerelease`，例如 `v1.0.0`、
  `v1.2.3-rc.1`。
- 输入可以不带 `v`（`1.0.0`），脚本归一化成 `v1.0.0`；文件名、`manifest.json`、
  `README.txt`、tag 一律用归一化后的同一串，不再出现 `v1.0.0` 与 `1.0.0` 并存。
- 非规范写法（`v1.0`、`dev`、`v1.0.0.0`、`nightly`）在出包前直接拒绝。
- 发行版本与运行时版本（`RUNTIME-VERSION` / `pr2_common/src/lib.rs` 的
  `RUNTIME_VERSION`）互相独立；后者变化表示语言包契约不兼容。

| 版本 | 用途 |
|---|---|
| `v0.9.0` | RC，未完成干净副本验收 |
| `v1.0.0` | 首次正式公开 |
| `v1.0.x` | 修复、文档、字体小修 |
| `v1.1.0` | 新语言包或明显功能 |
| `v1.2.0` | 新游戏版本（Steam / GOG 法语等） |
| `v2.0.0` | 语言包格式或运行时契约不兼容 |

## 2. 发行语言集

`src/release-languages.txt` 是唯一来源，一行一个语言代码，`#` 起注释。

- `release.ps1` 不带 `-Lang` 时只打这份清单；**不再自动扫描 `src/translations/`**。
- 清单里的每个语言必须同时具备：`src/packs/<lang>.toml`、`src/translations/<lang>.toml`、
  `src/font-map.ini` 的 `[<lang>]` 节；缺一样出包直接失败。
- 字体模式不在清单里标：`release.ps1` 默认 `-Fonts auto`，由 `font-map.ini` 的
  `[<lang>]` 四项映射决定——四项全是 `none` 的走 `config`（只带映射，用原版拉丁字体），
  其余走 `noto`（带实际字体）。`de` / `es` / `fr` / `it` 属于前者，`zh` / `ja` / `ko` / `ru` / `pl` 属于后者。
- `fr` 的译文键位对齐英文原文（`en.gog_1.1.2.3`，3548 条），其中 3279 条与 GOG 法语版
  原文（`fr.gog_1.1.2.42`）逐字相同，其余为补齐与修订；法语重音字符原版拉丁字体已覆盖，
  所以按 `config` 出包。
- `it` 同为英文原文键位，3548 条里 2892 条是意语，1 条原样保留，其余 655 条与英文原文
  逐字相同（城镇地名、船长与开发者人名、`IDM_` 标识符、纯图标签、占位串与符号集）；
  `de` / `fr` 在这批键上同样保留英文，属同一口径。意语用字在原版 `ARIAL.TTF` 覆盖内，
  所以按 `config` 出包。
- 新增一门语言：按[新语言](新语言.md)走完翻译与验收，再在清单里加一行。

当前清单：`zh`、`ja`、`ko`、`ru`、`de`、`es`、`fr`、`it`、`pl`。

### 2.1 发行分组

`src/release-bundles.toml` 决定哪些语言进同一个 zip。判据是**字体能不能共用**，不是语言系属：

| 分组 id | 语言 | 字体 |
|---|---|---|
| `latin` | `de` `es` `fr` `it` | 四项映射全 `none`，不打包任何字体，共用一份 `font-map.default.ini` |
| `zh` | `zh` | `NotoSansSC-Regular` + `NotoSerifSC-Black/Bold` |
| `ja` | `ja` | `NotoSansJP-Regular` + `NotoSerifJP-Black/Bold` |
| `ko` | `ko` | `NotoSansKR-Regular` + `NotoSerifKR-Black/Bold` |
| `ru` | `ru` | `PR2CyrBody-Regular` + `PR2CyrDisplay-Head/Black/Bold` |
| `pl` | `pl` | `PR2PlDisplay-Head/Black/Bold`（只换三个标题槽位，正文用原版 `ARIAL`） |

- `zh` / `ja` / `ko` / `ru` / `pl` 各带一套**文件名互不相同**的字体，合成一包不会省字体，只是多塞几十 MB，所以各出一包。
- 运行时不变：语言包仍是 `packs/<lang>.txt` 一门一个文件，启动器扫目录列出组内全部语言供切换；
  合的是**发行包**这一层。`locale.default.ini` 写分组里的 `default`。
- 组内语言字体模式必须一致（全 `none` 或全 `noto`）。混着就拒绝合包，避免包里一半带字体一半不带。
- 组内若出现同名 TTF 但内容不同（SHA-256 不等），出包直接失败，不允许后写的一份静默盖掉前一份。
- `pl` 的四个映射里 `ARIAL.TTF=none`、其余三个指向 `PR2PlDisplay-*`，`-Fonts auto` 因此判为
  `noto`，出包会带三个标题字体；它不能并进 `latin`（`latin` 的前提是组内零字体）。

## 3. 产物

每个分组一个 zip，命名固定（一个包同时面向 GOG 与 Steam，名字里不再区分入口）：

```
dist/PR2-<id>-<version>.zip              # id 是分组 id
dist/SHA256SUMS.txt
```

单语言分组的 `id` 就是语言代码，所以 `zh` / `ja` / `ko` / `ru` / `pl` 的产物名与合包前完全一样；
`latin` 一个 zip 顶原来的 `de` / `es` / `fr` / `it` 四份。

- `dist/` 只允许存在 `*.zip` 与 `SHA256SUMS.txt`。组装用的 stage 目录
  `PR2-<id>-<version>/` 打包后立即删除；上一次中断留下的同名目录在出包前清理。
- `SHA256SUMS.txt` 与 `sha256sum` 兼容：每行 `<大写 64 位 HEX><两个空格><文件名>`，
  UTF-8 无 BOM，按文件名排序，覆盖本次版本的全部 zip。
- 校验和在出包结束时由 `release.ps1` 统一生成，不在 CI 里另算一套。

## 4. 包内固定项

| 文件 | 要求 |
|---|---|
| `README.txt` | 第 1 行语言与适用版本（`GOG / Steam 通用`），第 2 行 `版本：<version>（运行时版本 <n>）` |
| `RUNTIME-VERSION` | 纯十进制整数，与 `pr2_common/src/lib.rs` 的 `RUNTIME_VERSION` 一致 |
| `manifest.json` | 见下；打包后立即校验，失败即拒绝出包 |
| `PR2Localization\packs\<语言>.txt` | 头部七行 `# pack-meta`：`alias`、`min_runtime`、`version=<不带 v 的发行版本>`，加编译期自动算出的 `entries`、`untranslated`、`scope`、`digest` |
| `OFL.txt` | `--fonts noto` 时必带 |

`manifest.json` 的字段（`schema 2`）：

| 字段 | 内容 |
|---|---|
| `schema` | 清单格式版本，当前 `2`（`target` 单值改为 `targets` 列表） |
| `package_id` | 包目录名，如 `PR2-zh-v1.0.0`、`PR2-latin-v1.0.0` |
| `lang` | 默认语言；合包时取分组的 `default` |
| `langs` | 包内全部语言代码，按分组清单顺序 |
| `edition` / `version` | 固定 `universal`（一个包面向两版）、归一化版本 |
| `runtime_version` | 与 `RUNTIME-VERSION` 相同 |
| `font_mode` | `noto` / `config` / `none` |
| `build` | `at`（UTC ISO8601）、`commit`（短 SHA，取不到为 `null`）、`dirty`（有未提交改动为 `true`） |
| `targets` | 两版各一条：`edition`、版本 id、说明、`PR2.exe` 的 SHA-256（取自 `KNOWN_BUILDS`） |
| `translation` | 默认语言的 `tags` / `review_status` / `source_lang` / `pack` / `delta`（见 §4.1） |
| `translations` | 包内每门语言一条：`lang`、`tags`、`review_status`、`source_lang`、`pack`、`delta`，顺序与 `langs` 一致 |
| `source` | `src/orig/<source_lang>.toml` 路径与 SHA-256 |
| `files` / `counts` | 逐文件类别、大小、SHA-256；文件数与总字节 |

`build` 只用于审计。

### 4.0 可复现构建

设置 `SOURCE_DATE_EPOCH`（秒）后，所有时间输出都取该值，不再取当前时间：

- zip 条目的 mtime 统一为该时间（早于 1980 的夹到 1980-01-01）；
- `manifest.json` 的 `build.at` 也取该时间。

因此同一个 commit、同一份字体源，重建出的包逐字节相同，校验和可比对：

```powershell
$env:SOURCE_DATE_EPOCH = (git log -1 --format=%ct).Trim()
.\release.ps1 -Version v1.0.0 -SkipInjector
```

`-SkipInjector` 要求 `build\injector-version.txt` 里记的版本与 `-Version` 相同；
首次重建、或改过运行时代码之后再出包，要先不带它跑一次，让构建更新那条记录。

不设该变量时行为与以前一致（mtime 取文件时间、`build.at` 取当前时间）。实现见
`src\tools\pack\build_time.py`（单一时间源），`make_zip()` 与 `release_manifest.py` 都从这里取。

### 4.1 译文标记

`src/packs/<lang>.toml` 的 `tags` 必填，描述“谁做的、怎么做的”，与完成度
（`review_status`）分开写：

| 标记 | 含义 |
|---|---|
| `official` | 官方本地化 |
| `retail` | 随零售版附带的官方本地化 |
| `fan` | 同人制作，非官方 |
| `community` | 社区协作，接受外部贡献 |
| `ai-assist` | AI 辅助起草，有人工审校 |
| `machine` | 纯机器翻译，未经人工校对 |

- 词表固定在 `src/tools/pack/pack_tags.py`，`config_check.py` 拒绝表外标记和重复标记；
  缺 `tags` 直接拒绝出包。
- 本项目自己的译文一律 `tags = ["fan", "community", "ai-assist"]`；
  从原版抽取的旧语言（如德语零售版）才用 `retail` / `official`。
- 标记在包根 `README.txt` 第 3 行显示为“标记：同人制作 · 社区协作 · AI 辅助；审阅：预览版”，
  并进 `manifest.translation.tags`。运行时语言包只带 `alias` / `min_runtime` / `version`
  三行元数据，游戏内 GUI 不显示标记。
- 语言包头的 `version`：`release.ps1 -Version` → `make_release.py` → `compile_pack.py --version`
  一路传下来，写的是归一化的不带 `v` 的版本（`version=1.0.0`）。启动器列表显示成
  `简体中文 · v1.0.0`。开发构建不传这个参数，头里就没有 `version` 行，列表只显示名字。
- 语言包头还有四行由编译过程自己算的内容描述，**不要手写，也不要拿它当版本号**：
  - `entries=<数据行总数>`、`untranslated=<占位未翻译条目数>`：原文本来就空的键
    （原版 `+++EMPTY+++`）不算欠译，所以 `untranslated` 不等于「没翻的条数」；
  - `scope=union`（GOG/Steam 合包用并集键集）或单个版本 id（`build\variants` 里的逐版包）；
  - `digest=<正文 sha256 前 12 位>`，**不含** `# pack-meta` 头 —— 换版本号不换摘要，
    同一份译文重打两次摘要相同；正文变一条摘要就变。
  启动器状态框显示成「3590 条 · 未译 0 · 摘要 9cfa2931c1c2」，玩家靠摘要判断
  「手上这份和新下那份是不是逐字相同」。
- `manifest.translations[].pack` 是**从包里读回来的**同一份头（`alias` / `version` /
  `entries` / `untranslated` / `scope` / `digest`），不另算一遍，两边不会分叉。
  摘要或条目数不合规（不是 12 位小写十六进制 / 不是数字）时这几个字段直接不写进清单，
  而不是把写坏的值当真。
- `manifest.translations[].delta` 是相对上一次发行的条目变化：
  `baseline`（基准 tag）、`kind`（`changed` / `same` / `initial` / `none` / `error`）
  和 `changed` / `added` / `removed` 三个数字。基准默认取 `release-v*` 里版本号最大、
  且不与本次版本同名的那一个，可用 `make_release.py --baseline-tag` 指定。
  基准里没有这份译文时记 `initial` 且**不给数字** —— 整份文件相加不叫变化。
  同样的文字也写进包根 `README.txt` 的「语言包变化」段。
- 同一版本号也编进 exe：`pr2_common/build.rs` 把 `PR2_VERSION` / `PR2_COMMIT` / `PR2_DIRTY`
  写进二进制，`PR2Localization.exe --version` 与 GUI 副标题读的就是它。两边同源，
  不会出现「包是 v1.0.0、exe 自称 dev」这种错位：`build_injector.ps1` 把这一批
  产物编进去的版本写进 `build\injector-version.txt`，`-SkipInjector` 出包时拿它与
  `-Version` 比对，不一致（或没有记录）直接拒绝出包，不靠人记着「正式发版别用」。
- 早期字段 `origin` / `ai_assisted` 已废弃，`config_check.py` 遇到即报错。

## 5. tag 与发布

- tag 名 `release-<version>`，与文件名里的版本完全一致（`release-v1.0.0`）。
- tag 必须是 annotated（`git tag -a -m "PR2 Localization <version>"`）。
- `-Tag` 要求工作树干净：有未提交改动就拒绝，避免把半成品标成已发布。
- 本地只出包不打 tag：`.\release.ps1 -Version v1.0.0 -NoPause`。
- 推送后由 `.github/workflows/release.yml` 在 `release-v*` tag 上重建同名包、
  校验产物齐全，并发布 GitHub Release（附全部 zip 与 `SHA256SUMS.txt`）。
- CI 的语言来自 `src/release-languages.txt`，分组来自 `src/release-bundles.toml`，
  与本地同一份清单，不再硬编码 `zh`/`ja`。

### 5.1 分支与发版线

**tag 只打在 `main` 上**，`dev` 不是发版分支。

| 分支 | 角色 | 允许的操作 |
|---|---|---|
| `main` | 稳定线，唯一发版来源 | 只从 `dev` 合并进来；只在这里打 `release-v*` tag |
| `dev` | 日常集成 | 功能分支合入；发版前先把 `origin/main` 合回 `dev` |
| `release/<series>` | 仅在需要并行维护旧版本时创建 | 从 `main` 切出，只放该系列的补丁 tag |

发版顺序：

1. `git fetch origin`
2. 把 `origin/main` 合进 `dev`，让 `dev` 包含 `main` 上所有已发布内容；
3. `dev` 推上去，开 PR 合并到 `main`（用 merge commit，保留 `dev` 历史）；
4. 在 `main` 上打 annotated tag：`git tag -a release-v1.0.0 -m "PR2 Localization v1.0.0"`；
5. 推 tag：`git push origin release-v1.0.0`，CI 从该 tag 重建并发布。

`release.yml` 里有一步 `Verify the tagged commit is on the release line`：tag 提交必须是
`origin/main` 或 `origin/release/*` 的祖先，否则直接失败。所以“在 `dev` 上随手打 tag”
不会产出 Release，也不会污染版本线。

什么时候才建 `release/1.x`：`dev` 已经在做下一个大版本，而 `v1.0.x` 还要出新补丁时，
从 `main` 切 `release/1.0`，补丁 tag 打在它上面；两者都满足上面的校验。没有这种并行需求前
不建，避免多一条要同步的分支。

## 6. 出包门禁

`release.ps1` 顺序执行，任一步失败即停：

1. 版本号归一化与格式校验；
2. `src/release-bundles.toml` 解析，逐个检查分组内语言的 pack / 译文 / 字体映射三件；
3. `src/tools/config_check.py`（locale、packs、translations、ui、font-map）；
4. `make_release.py`：`RUNTIME_VERSION` 与 Rust 常量比对 → 编译语言包 → 组装 →
   写清单并逐文件校验 → 打包 → 删 stage；
5. 生成 `SHA256SUMS.txt`；
6. 可选打 tag / 推 tag。

人工验收（干净副本、启动器、日志首行、原生入口、README 支持版本）见
[发行版 · 发版前验证](发行版.md#4-发版前验证)。

## 7. 与旧做法的差异

- 废止：`--version` 默认 `dev`、随便写版本串；自动扫描 `src/translations/*.toml` 当发行语言；
  `dist/` 里留 stage 目录；轻量 tag；只打印哈希不落盘。
- 保留：一入口一个 zip；两版都带 `PR2Localization\host\` 里的宿主代理
  （根目录不留同名 DLL、包内不带挂载脚本）；两版共用一个启动器入口和同一套还原动作；
  字体只做映射。
- 新增：同一份字体能共用的语言进一个 zip（`latin` = `de`+`es`+`fr`+`it`），
  运行时仍是语言包一门一个文件，启动器在包内切换。`pl` 已在发行语言集里，因带三个标题
  字体而单出一包（`PR2-pl-<version>.zip`）。
