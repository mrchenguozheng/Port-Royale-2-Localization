# 构建与安装

日常只需要一个入口（需要 Python 3.11+）：

```
start.bat
```

它只做一件事：把这个窗口打开（用 `pythonw.exe`，不弹黑框）。
**什么都不自动编译** —— 编译与复制都在窗口里点按钮触发，
所以只改了译文就只点「构建所选语言」，不用每次都重编 DLL。

窗口刚打开时会检查 `build\` 里的注入器产物，缺了就写在按钮旁边，
点一下「构建注入器」补上即可。

窗口按使用顺序分成三段，每段一个带边框的分组，段号就是步骤号：

```
┌ 1  构建 ────────────────────────────────────────┐
│   注入器   [构建注入器（DLL + 启动器）]  已就绪   │
│   语言包   ☑ zh   [构建所选语言]                  │
└──────────────────────────────────────────────────┘
┌ 2  部署到游戏目录 ───────────────────────────────┐
│   游戏目录 [...............] [浏览…] [复制到游戏目录] │
│   须含 PR2.exe。只复制构建产物，内容相同就跳过。   │
└──────────────────────────────────────────────────┘
┌ 3  启动 ────────────────────────────────────────┐
│   启动语言 [de ▾]  下拉本身不保存                │
│   [启动游戏（已注入）] [保存语言设置]             │
│   [运行游戏（原版）]                       [关闭] │
└──────────────────────────────────────────────────┘
  状态文字
  日志
```

日志在最后 —— 它是结果，不是入口。空闲时进度条自动隐藏，
因为一条 0% 的灰带看着像卡住了。窗口可缩放，拉高时是日志变高。

**日志只追加，从不清空。** 每次操作开始时插一条带时间戳的分隔行
（`── 构建语言包：zh ── 01:13:42`），几段记录靠它分开。
超过 4000 行时丢最老的那部分 —— 上限是为了不让 `Text` 控件越用越慢，
而不是为了腾地方，所以刚发生的操作一定还在。

## 窗口里的按钮

| 按钮 | 所在段 | 作用 | 何时可用 |
|---|---|---|---|
| 构建注入器 | 1 构建 | 编译 `PR2TextSource.dll` 与 `PR2Launcher.exe` | 空闲时 |
| 构建所选语言 | 1 构建 | 编译勾选的语言，进度条 + 日志实时显示 | 空闲时 |
| 复制到游戏目录 | 2 部署 | 把产物复制进游戏目录 | 注入器在位 + 构建完成 + 已选游戏目录 |
| 启动游戏（已注入） | 3 启动 | 用 `PR2Launcher.exe` 启动；语言**确有变化时**顺手写入 `locale.ini` | 该目录已复制过 |
| 保存语言设置 | 3 启动 | 只写入 `locale.ini`，不进游戏 | 语言确有变化 |
| 运行游戏（原版） | 3 启动 | 直接跑 `PR2.exe`，不注入也不保存 | 选中有 `PR2.exe` 的目录 |
| 关闭 | 3 启动 | 关窗，什么都不做 | 一直可用 |

「启动游戏（已注入）」已经**含有**保存行为，所以没有单独的
「保存设置并启动」和「启动（不保存）」—— 那两个的区别只是写不写文件，
而写不写由「有没有变化」决定，不该让用户在两个按钮之间选。
「保存语言设置」补的是另一种需求：想改配置但暂时不进游戏。

「保存语言设置」在没有变化时是灰的 —— 按钮本身就是
「这里有东西要落盘」的提示，亮着却什么都不做等于骗人。

「构建注入器」与「构建所选语言」是**两条独立的链路**，不互相依赖：

| | 构建注入器 | 构建所选语言 |
|---|---|---|
| 输入 | `src\injector\` 下的 C/C++ 源码 | `src\translations\*.toml` |
| 工具链 | Visual Studio（C++ 桌面开发组件） | 纯 Python |
| 耗时 | 约 4.5 秒 | 约 0.5 秒（需要重裁字体时约 15 秒） |
| 什么时候需要 | 改了 C++ 源码 | 改了译文 |

所以日常改翻译只需要点后者，不必每次都付编译 C++ 的时间，
也意味着**只想改译文的人不装 Visual Studio 也能用**。


## 版本识别与目录记忆（第 2 段顶部）

选过游戏目录后，窗口会用 `PR2.exe` 的 **SHA-256** 认出这是哪个构建，并把
「版本 → 目录」记进设置文件；下次打开窗口自动恢复上次的目录。

已知构建（哈希为实测值，见 `src/tools/pr2ctl/core.py` 的 `KNOWN_BUILDS`）：

| 版本 | SHA-256（前 12 位） | 说明 |
|---|---|---|
| GOG 英文版 1.1.2.3 | `394CE2A48BC6…` | 原版英文，自带 `PR2Packs\` |
| GOG 法语版 1.1.2.42 | `EF0E97D40F8D…` | 法文界面文本编在 exe 里；版本号比英文高 |
| Steam 英文版 1.1.2.3 | `5295C06689…` | 带 CEG 校验，exe 不可改，只能注入 |

- **已知版本**：下拉框里显示「版本名 — 目录」，选中即切换目录；
- **未知版本**：仍可记住（标「未知版本」），只是没有版本名；
- **同版本换目录**：会更新该版本记录的目录（一个版本只记一个位置）；
- **设置文件**：默认 `%LOCALAPPDATA%\PR2Localization\settings.json`，
  可用环境变量 `PR2_SETTINGS` 指定别处。文件里只存版本哈希与目录，不含译文。

**检查补丁…** 按钮给出游戏目录的实际状态，逐项列出：

| 项目 | 判据 |
|---|---|
| `PR2.exe` | 是否存在（目录有效性的前提） |
| `PR2Launcher.exe` / `PR2TextSource.dll` | 注入组件是否已复制 |
| `PR2Packs\` | 装了哪些语言包（列出代码名） |
| `PR2Packs\locale.ini` | 游戏会加载哪个语言 |
| `fonts\*.TTF` | 与仓库 `assets/fonts/original/` 比对：原版 / 已替换 / 缺失 / 无法比对 |

这项检查**只读**，不改任何文件；它回答的是「补丁装没装、装的哪一版」，
不判断游戏能否正常启动。

## 语言包与字体一起构建

「构建所选语言」不只是编语言包（`build\PR2Packs\<语言>.txt`），
**还会顺手检查字体**：

- 游戏自带字体没有中文字形，中文要靠 `build\fonts\*.ttf`（从全量字体
  按「当前译文用到的字」裁剪出来的）；
- 每次构建都会对比：**当前译文里的字，现有字体是否都能画**。全都覆盖就
  直接跳过；一旦出现新字（比如新补的「嫩」），自动重裁四个字体，日志里会
  逐行写 `字体：…` 和每个字体的大小变化；
- 字体失败**不会**让构建失败（语言包本身是好的），只在日志里说明原因。

重裁需要两样东西，缺了会给出提示、不会中断：

| 需要 | 说明 |
|---|---|
| 全量字体 | 默认 `<游戏目录>\fonts\_orig_bak`；可用环境变量 `PR2_ORIG_FONTS` 或 `subset_fonts.py --src` 指定 |
| fontTools | `python -m pip install fonttools`；也可用 `PR2_FONTTOOLS_SITE` 指向已装好的 site-packages |

之后点「复制到游戏目录」时，`build\fonts\*.ttf` 会和语言包一起复制过去，
**字体不再需要手工拷**（以前漏掉这一步的表现就是中文缺字、显示空白）。

关窗不复制不算失败。**复制与启动是分开的** —— 复制完窗口不会关，
可以直接点「启动游戏（已注入）」；「运行游戏（原版）」用来对比
同一个界面到底变没变。

## 译文编辑器（第 4 段）

第 4 段只有两个按钮：「打开译文编辑器」和「停止编辑器」。编辑器由这个
窗口**负责起停**，不需要另外记着去关。

**不需要装任何依赖。** 编辑器的后端是纯标准库（`http.server`），前端是
已经构建好的 `dist\`，所以有 Python 就能开 —— 不会建 venv，也不会联网。

**一页一取，底栏翻页。** 默认每页 100 条（可切 50 / 200），底栏写
「第 N / M 页 · 共 X 条」，点箭头或直接输页码都能翻；搜索命中同样按这个
分页。改过的条目跨页保留，点一次「保存」会把所有改动一起提交。

**参照列会标出「该版本无此条」。** 两份原版表条数不同（英文 1.1.2.3 共 3548 条、法语 1.1.2.42 共 3571 条），列表以**英文**为准；法语版里没有的那 19 条（2004 竞赛日志之类）在法语列显示成灰斜体的「（该版本无此条）」，和「空译文」区分开。

**＋ 添加语言。** 点「编辑」右边的 ＋，填一个语言代码、选一个已存在的语言
当模板，确认后就把那份译文复制成新语言（`src\translations\<代码>.toml`），
并自动切过去。代码要字母开头、只含字母/数字/`-`/`_`；**输入时就会实时检查**，
已存在的名字当场标红并把「创建」置灰，服务端写盘那一步还用独占创建兜底
（`O_EXCL`），所以**不会覆盖**任何已有文件。新语言在工具窗口「构建所选语言」
的勾选列表里要**重开窗口**才出现 —— 那个列表是窗口启动时扫一次。

**再点一次不会起第二个。** 窗口先做一次 TCP 探测，再问
`http://127.0.0.1:<端口>/api/health`；答话的是编辑器就直接开浏览器、
复用那一个。服务启动时端口被占会往上找空位，所以探测是从 8777 往后扫一段。

**关掉本窗口会把编辑器一起停掉**：先请服务自己走 `/api/shutdown` 退出，
不响应再 `taskkill /T` 杀整个进程树。服务另有自己的控制台窗口，
里面是地址和报错；关掉那个窗口同样等于停服务。

| 按钮 | 作用 |
|---|---|
| 打开译文编辑器 | 起一个（或复用已在跑的）；浏览器自动打开 `http://127.0.0.1:8777/` |
| 停止编辑器 | 已知在跑时才亮；停掉后自动变灰 |

## 语言怎么定的

运行时**只有一种语言生效**，由下面三条按优先级决定：

| 优先级 | 来源 | 作用范围 |
|---|---|---|
| 1 | 环境变量 `PR2_PACK_LANG` | 只影响这一次启动 |
| 2 | `PR2Packs\locale.ini` 的 `language=` | 持久生效，默认走这条 |
| 3 | 编译进 DLL 的兜底值 `zh` | 连 ini 都没有时 |

**GUI 的「启动语言」下拉管的是第2 条。** 选定游戏目录时，窗口读那份
`locale.ini` 并把结果显示在下拉框里；**改下拉只是记录选择**。

保存推迟到按钮，是为了不留痕：随手点一下下拉、或者选错了没保存，
游戏目录里不该凭空多出一个 `language=`。

### 什么时候才写文件

落盘只有一条路径（`save_lang_choice`），两个入口共用：
「启动游戏（已注入）」和「保存语言设置」。前者是顺带保存 ——
语言确有变化才写；后者给「只想改配置、不进游戏」用。

**能不写就不写。** 下面两种情况连一个字节都不动，但游戏照样启动、
照样用下拉里那个语言（走第 1 条的环境变量）：

| 情况 | 为什么不写 |
|---|---|
| 选的是「跟随 locale.ini」 | 本来就没有要保存的东西 |
| 游戏目录里已经是这个语言 | 写回去是逐字节相同的事 |

第二条不只是省一次写盘：重写相同内容会改文件时间戳，
时间一长就分不清「这个设置是我改的，还是程序重写了一遍」。
「我到底动过它没有」必须可查，所以无变化时明确不写。
副作用是 `build\PR2Packs\locale.ini` 和游戏目录那份可能不同步 ——
前者只在下一次构建时用来兜底，不参与运行时判定，可以接受。

落盘时写两处：`build\PR2Packs\locale.ini` 与游戏目录那份。
前者保证下次构建不会把选择打回模板默认值（`run_build` 只在文件不存在
时才用模板），后者让下一次启动直接生效，不必先构建一次。

写不成不算失败 —— 本次启动仍会用所选语言（靠 `--lang` 走环境变量），
只是下次启动会回退，所以只提示不弹窗打断。

下拉的选项来自**游戏目录里已装的 `.txt`**，不是 `src\translations\`
的源文件 —— 那边的还没编译，装不进去。

第 1 条是给命令行的：直接双击 `PR2Launcher.exe` 行为与从前完全一致
（读 `locale.ini`）；而从别的程序调它时可以带一个**不落盘**的临时语言：

```
PR2Launcher.exe --lang=de     本次跑 de.txt，不改任何文件
PR2Launcher.exe               用 locale.ini 里的语言
PR2Launcher.exe --help        用法
```

`--lang` 的值只允许字母数字和连字符（它要拼进文件路径，放任 `../`
就是目录穿越），非法值直接报错退出。

读不到设置时，窗口会分别说明原因，而不是留一个说不清的下拉框：

| 情况 | 下拉显示 | 状态文字 |
|---|---|---|
| 正常 | 那个语言 | 当前语言：xx（读自 PR2Packs\locale.ini）。 |
| ini 里没有 `language=` | 跟随 locale.ini | …里没有 language=，游戏会显示英文。 |
| ini 指向没装的包 | 跟随 locale.ini | …指定 xx，但游戏目录里没有 xx.txt —— 游戏会显示英文。 |
| 根本没有 ini | 跟随 locale.ini | 找到 PR2.exe，但没有 PR2Packs\locale.ini —— 语言未设置… |
| 还没复制过去 | 跟随 locale.ini | 找到 PR2.exe，但还没有 PR2Packs\ —— 先构建并复制过去。 |

「跟随 locale.ini」= 不干预，状态文字会报出文件里真实的值。
选了别的语言但文件只读时，窗口会提示**本次启动仍用新语言、
但下次启动会回退** —— 此时游戏照常能跑，所以只提示不打断。

> 语言包没加载成功时，`PR2TextSource.log` 第一行会写
> `NO pack loaded: language 'xx' from …`。以前这种失败在屏幕上完全
> 看不出来（表现和「没汉化」一样），现在能一眼定位。

复制会**先比 hash，内容相同就跳过不覆盖** —— 反复点不会
反复改写 DLL 与语言包，游戏正在运行时也不会撞上文件占用。
`PR2Packs\` 里本次不装的语言会被移除。

`PR2.exe` 全程不被修改。复制好之后用游戏目录里的 `PR2Launcher.exe`
启动，语言包在启动时读取 —— 改完翻译只要重新构建 + 重新复制。

## 开发者：一条命令打补丁

改完译文不想点窗口？用 `apply_patch.bat`（或 `python src/tools/apply_patch.py`）：

```powershell
apply_patch.bat                 :: 构建 ja + zh，部署到上次的游戏目录
apply_patch.bat --langs ja      :: 只弄日语
apply_patch.bat --launch        :: 部署完直接启动
apply_patch.bat --dry-run       :: 只打印计划，不动文件
```

它按顺序做五步，**任何一步失败就停**：

1. `normalize_text`（日语带 `--particles`；没装 janome 自动跳过并提示）
2. `check_breaks --strict`（换行/占位符不一致直接失败）
3. `compile_pack`（含字体重裁；字体已覆盖时跳过）
4. `deploy`（复制启动器、DLL、字体、语言包、locale.ini）
5. **核对**：逐个比对构建产物与游戏目录里文件的 SHA-256，不一致就报错

游戏目录的确定顺序：`--game-dir` > 设置里的 `last_dir` > 已记住版本里第一个。
版本会用 `PR2.exe` 的哈希认出来并打印。

两点注意：

- 部署会**移除本次没有列出的旧语言包**（例如 `test_en.txt`），这是为了让目录和
  `--langs` 保持一致；
- 游戏正在运行时文件被占用，第 4 步会失败并提示先关游戏。


### 可选：依存句法补空格（`--dep`）

`apply_patch.bat --langs zh --dep` 会在生成 `zh.toml` 之后，用 spaCy 的依存分析
给**长度 ≥60 字的段落**在「长主语 ↔ 谓语」处补空格。默认关闭。

```powershell
python src\tools\zh_dep_space.py --dry-run    # 出 CSV + 抽样，不改文件
python src\tools\zh_dep_space.py --apply      # 写回 zh.toml
```

它需要 `.venv-spacy`（或 `PR2_SPACY_PYTHON`）。规则只动 nsubj 边界，且断点
后面不能是名词/形容词，避免把「大片陆地」拆开；标签与占位符序列处理前后
会校验一致，不一致直接中止。

## build 目录

`build\` 全部是产物，**可以整个删掉重建**。

`build\PR2Packs\` 是**累积目录**：多次构建的语言包会并存，而
`locale.ini` 只指向其中一个。安装时只复制本次构建的那几个，
不会把上次残留的语言一起塞进游戏目录。

`locale.ini` 例外 —— 它**不是**每次构建都从 `src\locale.ini` 覆盖。
只有文件不存在时才用模板建一份，否则用户在 GUI 里选的语言会被
打回默认值。日志里会明说「已保留现有 PR2Packs\locale.ini（xx）」。

> `src\locale.ini` 因此只是**首次安装时的默认值**，不是持续来源。
> 之后语言由 `build\PR2Packs\locale.ini` 和游戏目录那份决定。

## 脚本

| 脚本 | 职责 |
|---|---|
| `start.bat` | 打开本地化工具窗口，不自动编译 |
| `src\find_python.bat` | 定位 Python，逐个试 PATH/安装目录的候选 |
| `src\build_injector.bat` | 编译 `PR2TextSource.dll` 与 `PR2Launcher.exe` |
| `src\build_translation.bat` | 编译语言包（`locale.ini` 已存在则保留） |

四个 `.bat` 都必须保持 **ASCII + CRLF**，cmd 解析 LF 的 label 不可靠。
用 `sed -i` 改过之后要确认换行符没被冲掉。

`find_python.bat` 为什么要逐个试：PATH 上第一个 `python` 未必能正常运行
（编辑器自带的那个就没有），只试第一个会在弹窗那一步才炸。

## Python 脚本

`src\tools\`：

| 脚本 | 做什么 | 命令 |
|---|---|---|
| `translate.py` | 译文流水线：合并所有语言、导出待译条目、校验、看进度 | `status` / `export` / `check` |
| `new_lang.py` | 新建一种语言的译文文件（复制 en.gog_1.1.2.3.toml 或 fr.gog_1.1.2.42.toml） | `--new-lang <代码> [--from en\|fr]` |
| `apply_patch.py` | 归一化→校验→编译→部署→核对，一条命令 | `[--langs ja,zh] [--game-dir …] [--launch]` |
| `space_words.py` | 按词给中文补空格（超宽长串才会动），解决整行裁切/空白 | `--lang zh [--apply]` |
| `compile_pack.py` | 把 toml 编译成引擎能读的语言包，并校验占位符 | `--lang <代码>` |

依赖方向是单向的：`start` 的 Web 页面（`src/editor`）→ `pr2ctl`（核心）→ `compile_pack.py` → `translate.py`。
语言列表只在 `translate.target_langs()` 里定义一次，别处都问它。

也可以不用界面，直接在命令行编：

```
python src\tools\compile_pack.py            # 默认 zh
python src\tools\compile_pack.py --lang de
```

### 中文分词（`space_words.py`）

默认用 spaCy 的 `zh_core_web_sm`（活跃维护，OOV 比 jieba 稳）。spaCy 的依赖在
Python 3.14 上还没有轮子，所以要用 3.11 装一份、再用环境变量指过去：

```powershell
py -3.11 -m pip install "spacy==3.7.5" "spacy-pkuseg==0.0.33"
py -3.11 -m spacy download zh_core_web_sm
set PR2_SPACY_PYTHON=<Python311 的 python.exe>
python src\tools\space_words.py --lang zh --dry-run
```

注意版本要一起钉：spaCy 3.8 + spacy-pkuseg 1.x 会因 numpy 2 的 ABI 报
`numpy.dtype size changed`；3.7.5 + 0.0.33 + numpy 1.26 是能跑的组合。
没装 spaCy 时脚本自动退回 jieba（质量差一些）。

> 选型备注：HanLP 2.1 / LTP 4 都依赖 torch（光轮子就 1.8 GB），只为给 3,548 条
> 中文找个换行点不值得，所以本项目只用 spaCy；`.venv-hanlp` 不再使用。

### Web 安装页（Phase 2）

编辑器与安装页合并成同一个工作台：顶部「译文编辑 / 安装与启动」页签在**同一页面内**切换（`/#start`），不再整页跳转；`/start` 只做跳转。

- 游戏目录：输入路径 → 「检测并记住」（写回 settings，按 PR2.exe 的 SHA 归档）；
- 状态：版本、已装语言包、locale.ini；
- 构建 / 部署：后台线程执行，日志实时轮询到页面；
- 启动：已注入启动、原版对比、打开编辑器；
- 接口：`/api/start/status`、`/api/start/dir`、`/api/start/build`、`/api/start/deploy`、`/api/start/launch`、`/api/start/job`。

`start.bat` 打开 `/start`；tkinter 窗口已移除。

### locale.ini 的定位

`PR2Packs\locale.ini` 是**引擎契约**（DLL 启动时读它），格式必须保持 `language=xx`，
不适合换成 JSON/YAML。要重构的是「谁写它」而不是格式：

- **唯一写入口**：`pr2ctl.set_game_language(game_dir, code)`，同时更新游戏目录与
  `build\PR2Packs\locale.ini` 模板，并记进 settings 的 `language`；
- **构建/部署不再偷偷改语言**：`apply_patch` 默认保持现有 `locale.ini`，
  要改显式加 `--locale ja`；
- **Web 安装页**有「设为游戏语言」按钮（`/api/start/lang`）；
- 启动游戏时优先用页面选的语言，缺省回落到 `locale.ini`。

这样语言选择只在一处落地，不会再出现「部署顺序决定游戏语言」。

### 服务状态与残留进程

安装页新增「服务状态」卡片：

- 当前服务：pid、端口、已运行时长、Python 版本、前端产物构建时间；
- 端口范围内（8777–8800）所有编辑器实例：当前 / 其它，其它实例可一键「停止」；
- 接口：`/api/health`（详细）、`/api/server/instances`、`/api/server/stop`。

`start.bat` 在前台运行服务并保留窗口：能直接看到启动信息与每次 `/api/*` 请求的日志，关窗口（或 Ctrl+C）即停服务。它带 `--restart`，启动前会停掉 8777 上的旧实例；其它端口上的残留可在页面上停。
命令行也可以：`start.bat --status` 列出实例，`python src/tools/server_status.py --stop 8779` 停掉指定端口。
