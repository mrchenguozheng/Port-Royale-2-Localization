# 构建与安装

日常只需要一个入口（需要 Python 3.11+ 且**带 tkinter**）：

```
src\build_n_patch.bat
```

它先编译注入器，然后弹出一个窗口：勾选语言、构建、选游戏目录安装。

---

## 窗口里的五个按钮

| 按钮 | 作用 | 何时可用 |
|---|---|---|
| 构建所选语言 | 编译勾选的语言，进度条 + 日志实时显示 | 构建/安装时不点 |
| 安装 | 把产物复制进游戏目录 | 构建完成 + 已选游戏目录 |
| 运行游戏 | 用 `PR2Launcher.exe` 启动（带汉化） | 该目录已安装过 |
| 原版启动 | 直接跑 `PR2.exe`，不注入 | 选中有 `PR2.exe` 的目录 |
| 关闭 | 关窗，什么都不做 | 一直可用 |

关窗不装不算失败。**安装与启动是分开的** —— 装完窗口不会关，
可以直接点「运行游戏」；「原版启动」用来对比同一个界面到底变没变。

安装会**先比 hash，内容相同就跳过不覆盖** —— 反复点安装不会
反复改写 DLL 与语言包，游戏正在运行时也不会撞上文件占用。
`PR2Packs\` 里本次不装的语言会被移除。

`PR2.exe` 全程不被修改。装好后用游戏目录里的 `PR2Launcher.exe`
启动，语言包在启动时读取 —— 改完翻译只要重新构建 + 重新安装。

---

## 单独跑

```
src\build_injector.bat      -> build\PR2TextSource.dll / PR2Launcher.exe
src\build_translation.bat   -> build\PR2Packs\zh.txt + locale.ini
```

编译需要 Visual Studio（C++ 桌面开发组件），详见[注入组件](注入组件.md#编译)。

---

## build 目录

`build\` 全部是产物，**可以整个删掉重建**。

`build\PR2Packs\` 是**累积目录**：多次构建的语言包会并存，而
`locale.ini` 只指向其中一个。安装时只复制本次构建的那几个，
不会把上次残留的语言一起塞进游戏目录。

## 脚本

| 脚本 | 职责 |
|---|---|
| `src\find_python.bat` | 定位 Python。`--tk` 参数要求带 tkinter，会逐个试所有候选 |
| `src\build_injector.bat` | 编译 `PR2TextSource.dll` 与 `PR2Launcher.exe` |
| `src\build_translation.bat` | 编译语言包 + 复制 `locale.ini` |
| `src\build_n_patch.bat` | 前两步 + 弹窗 |

`find_python.bat` 为什么要逐个试：PATH 上第一个 `python` 未必带 tkinter
（编辑器自带的那个就没有），只试第一个会在弹窗那一步才炸。

## Python 脚本

`src\tools\`：

| 脚本 | 做什么 | 命令 |
|---|---|---|
| `translate.py` | 译文流水线：合并所有语言、导出待译条目、校验、看进度 | `status` / `export` / `check` |
| `new_lang.py` | 新建一种语言的译文文件（复制 en.toml 或 fr.toml） | `--new-lang <代码> [--from en\|fr]` |
| `compile_pack.py` | 把 toml 编译成引擎能读的语言包，并校验占位符 | `--lang <代码>` |
| `build_install.py` | 构建与安装窗口（就是 `build_n_patch.bat` 弹出的那个） | `--build` |

依赖方向是单向的：`build_install.py` → `compile_pack.py` → `translate.py`。
语言列表只在 `translate.target_langs()` 里定义一次，别处都问它。

也可以不装 tkinter，直接在命令行编：

```
python src\tools\compile_pack.py            # 默认 zh
python src\tools\compile_pack.py --lang de
```
