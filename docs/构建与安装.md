# 构建与安装

## 入口

日常只需要（PowerShell 7 + Python 3.11+）。译文直接编辑
`src\translations\<语言>.toml`，构建与部署走命令行：

```powershell
.\apply_patch.ps1                 # 归一化 → 校验 → 编译 → 部署 → 核对
.\build.ps1                       # 注入器 + 语言包
python src\tools\pack\compile_pack.py --lang zh --strict   # 只出语言包
```

部署完成后用发行版 `PR2LocalizationGUI.exe` 选语言、启动游戏，
见 [发行版](发行版.md)。

## 单条快路径（agent / 手工反馈用）

日常修正一条译文时，不必走完整构建链。`quick.py` 只做：

1. 按截图里的文本，在中文/英文/法文里找候选 hash；
2. 或按已知 hash 直接改 `src/translations/<lang>.toml` 的一条；
3. 调用 `compile_pack --no-fonts` 生成新的 `build/runtime/PR2Localization/packs/<lang>.txt`；
4. 只把这个 `.txt` 复制进游戏目录，不动 DLL、启动器和字体。

```powershell
# 先查候选，不改文件
python src\tools\pack\quick.py --lang zh --find "截图里看到的一句"

# 确认 hash 后改一条并部署
python src\tools\pack\quick.py --lang zh --id 0xc4bde7d1 --text "修正后的译文"

# 只改文件并生成 pack，不复制到游戏
python src\tools\pack\quick.py --lang zh --id 0xc4bde7d1 --text "修正后的译文" --no-deploy
```

`--find` 同时搜中文、英文、法文；带 `--text` 时只有唯一候选才允许自动写入，
否则必须显式给 `--id`。占位符/标签校验仍走 `shared\core\validate.py`：
错误始终拒绝；警告默认拒绝，确认无误可加 `--force`。

它**不做**全量 `check_breaks`、字体检查、运行时复制和全文件 SHA 核对。
这些仍属于发布前的完整构建。游戏启动时读取语言包，所以改完要重启游戏。

agent 需要结构化结果时加 `--json`；查找返回 `candidates`，写入返回
`id/pack/pack_sha256/deployed`。

## 部署

`apply_patch.ps1`（或 `python src\tools\pack\apply_patch.py --langs zh`）把
`build\runtime\` 复制进游戏目录：

- 只复制文件，不改 `PR2.exe`；
- 内容相同的文件按 SHA-256 跳过，不反复重写；
- 本次没选的语言包会从游戏目录移除；`packs\overrides\` 是本机临时覆盖，整目录保留；
- 字体放到 `PR2Localization/fonts/`，不按语言单开子目录，**不覆盖根目录原版**；
- Steam 版最后单独换宿主 DLL：先校验原版、写两份备份，再复制成 `Ascaron.Logging-2.6.dll.new`、
  校验通过后换名覆盖，失败时根目录那份仍是原样；宿主 DLL 不走普通文件复制。
  同样的动作玩家侧由启动器在启动前触发（`ensure_steam_host`），部署侧由
  `pr2ctl/deploy.py` 调 `steam_host.py`；
- 只写 `locale.default.ini`，已有用户 `locale.ini` 不会被部署改掉（空值也不动）。

记住的游戏目录和版本在：

```
%LOCALAPPDATA%\PR2Localization\settings.json
```

可用环境变量 `PR2_SETTINGS` 改位置。里面只存路径和版本，不存译文。
第一次用 `--game-dir <路径>` 认定目录，之后会被记住。

## 启动

| 入口 | 作用 |
|---|---|
| `PR2LocalizationGUI.exe` | 发行版玩家界面：读语言列表、写 `locale.ini`、启动/结束进程 |
| `PR2Localization.exe --lang=zh` | 按指定语言启动这一次，不写 `locale.ini` |
| `PR2.exe` | 原版对比，不注入 |

## 语言怎么定的

运行时只有一种语言生效：

| 优先级 | 来源 | 范围 |
|---|---|---|
| 1 | 环境变量 `PR2_PACK_LANG` | 本次启动；`PR2Localization.exe --lang=xx` 设置 |
| 2 | `PR2Localization/packs/locale.ini` 的 `language=` | 用户选择；存在即优先，空值也保留 |
| 3 | `PR2Localization/packs/locale.default.ini` 的 `language=` | 活动文件不存在时的发行默认 |
| 4 | DLL 内置兜底 `zh` | 两个文件都没有时 |

因此：

- 发行版 `PR2LocalizationGUI.exe` 启动成功后写第 2 条；
- `PR2Localization.exe --lang=xx` 只给本次传语言，不写文件；
- 直接双击 `PR2Localization.exe` 只读第 2 条；
- 直接运行 `PR2.exe` 不经过启动器，也不做版本检查。

## 版本识别

部署链与发行版 GUI 用 `PR2.exe` 的 SHA-256 认出已知构建：

| 版本 | 说明 |
|---|---|
| GOG 英文 1.1.2.3 | ✅ 已实测 |
| GOG 法文 1.1.2.42 | ❌ 不支持，只用作翻译参照 |
| Steam 英文 1.1.2.3 | ✅ 已实测（宿主 DLL 代理） |

未支持的版本只用于识别/提示，不要部署，也不属于支持范围。

未知版本也可以记住，只是没有名字。版本名和哈希常量在
`src/tools/install/pr2ctl/base.py`。

## 字体

字体只做映射，不做缝合，也不由界面生成：完整 Noto 静态字重（俄语走
`build_cyr_fonts.py` 的四个自建文件）由仓库侧脚本产出，平铺到
`build/runtime/PR2Localization/fonts/`（不按语言单开子目录），由
`font-map.default.ini` 把四个逻辑名映射到实际文件。

要自定义映射时写同目录的 `font-map.ini`，只写需要覆盖的逻辑名；运行时以默认文件
为基础按项叠加；解压升级不会覆盖它。也可以只带默认映射文件（`--fonts config`），
但必须把映射中写明的实际字体放进 `PR2Localization\fonts\`。
详见 [发行版](发行版.md) 与 [字体与分发](字体与分发.md)。

**部署来源（2026-11-21 实机验收时修的两处）。** 这两处都会让字体映射「看着配好了、游戏里却没生效」：

1. **默认映射以 `src\font-map.ini` 为准。** 以前部署复制的是
   `build\runtime\PR2Localization\fonts\font-map.default.ini`，那份是派生物、会落后于模板——
   `[pl]` 一节就是这么丢的：游戏里 pl 的四个逻辑名一个都没配，标题回退原版。
   现在 `deploy_steps` 直接拿 `src\font-map.ini` 当默认映射的源，runtime 那份只在模板缺失时兜底。
2. **语言子目录里的字体要平铺复制。** 新字体生成在
   `build\runtime\PR2Localization\fonts\<语言>\`，而游戏只认 `fonts\` 根下的文件名。
   旧逻辑「根下有 ttf 就只复制根下那批」，结果 `<语言>` 子目录里的一个都没进游戏
   （pl 的 `PR2PlDisplay-Head/Black/Bold.ttf` 就这样被漏掉）。现在除了平铺那批，
   还会把**当前语言**子目录里的 ttf 平铺复制过去，别的语言仍然不拷，保持「一次安装一个语言」。


```powershell
python src\tools\font\make_noto_fonts.py --lang zh --out <目录>
```

## 译文文件

一种语言一个文件，直接编辑：

- 路径 `src\translations\<代码>.toml`，每条一行 `"0xhash" = "译文"`；
- 没写的条目游戏里显示英文；
- 加语言：`python src\tools\pack\new_lang.py --new-lang <代码> --from en`；
- 改完跑 `.\apply_patch.ps1` 或 `python src\tools\pack\quick.py --lang zh --id 0x… --text "…"`。

语言包元数据（显示名、GUI 语言、最低运行时）在：

```
src/packs/<代码>.toml
```

编译时写入语言包头部。旧语言包不再兼容，详见
[发行版](发行版.md)。

## 开发者命令

改完译文，一条命令跑完：

```powershell
.\apply_patch.ps1                 # 构建 ja + zh，部署到上次的游戏目录
.\apply_patch.ps1 --langs ja      # 只弄日语
.\apply_patch.ps1 --launch        # 部署完直接启动
.\apply_patch.ps1 --dry-run       # 只打印计划
```

它按顺序做：

1. 归一化标点（只改标点；排版空格在编译期由 lang_rules 的 spec 补，不写回译文）；
2. `check_breaks --strict` 校验换行/占位符；
3. 编译语言包（默认含字体生成）；
4. 部署到游戏目录；
5. 逐个文件比对 SHA-256。

### 一键构建

根目录 `build.ps1` 把注入器和语言包收成一个入口：

```powershell
.\build.ps1                         # 注入器 + 全部语言包
.\build.ps1 -Target Packs           # 只编语言包
.\build.ps1 -Target Packs -Lang zh  # 只编中文
.\build.ps1 -Target Injector        # 只编 Rust 注入器
```

默认从 `src\translations\*.toml` 发现语言，所以新增语言后不需要改脚本。
低层脚本仍然保留，排查单步问题时可以直接跑：

```powershell
.\src\build_injector.ps1
.\src\build_translation.ps1 -Lang zh
.\src\build_translation.ps1 -Lang ja
```

### 一键发版

根目录 `release.ps1` 负责“构建运行时 → 生成 zip → 可选 tag/push”：

```powershell
.\release.ps1 -Version v1.0.0                 # 每个分组一个 zip（GOG / Steam 通用）
.\release.ps1 -Version v1.0.0 -Bundle zh       # 只出中文分组
.\release.ps1 -Version v1.0.0 -Bundle latin    # 只出 latin 分组（de+es+fr+it 一个包）
.\release.ps1 -Version v1.0.0 -Lang zh          # 旧口径：一语言一包（仍是一个通用包）
.\release.ps1 -Version v1.0.0 -Tag
.\release.ps1 -Version v1.0.0 -Tag -Push
```

- 默认按 `src\release-bundles.toml` 的分组出包：同一份字体能共用的语言进一个 zip。
  `de` / `es` / `fr` / `it` 四项映射全 `none`，合成 `latin` 一包；`zh` / `ja` / `ko` / `ru`
  各带一套字体，各出一包。`-Bundle <id>` 只出指定分组；`-Lang` 走旧口径（一语言一包），两者互斥；
- 分组里的语言必须都在 `src\release-languages.txt` 里；
- 一个包同时面向 GOG 与 Steam，启动器按游戏目录判版，所以没有按入口分包的开关；
- 默认先构建注入器，已有 `build\runtime` 时可加 `-SkipInjector`；
- 默认 `-Fonts auto`：按 `src\font-map.ini` 的 `[<lang>]` 四项映射决定每门语言的模式，
  四项全是 `none` 的走 `config`（只带映射，用原版拉丁字体），其余走 `noto`（带实际字体）。
  自用测试可加 `-Fonts none` 避免生成大文件；`-Fonts config` 强制全部只带映射，
  只复制 `src\font-map.ini` 为 `PR2Localization\fonts\font-map.default.ini`，
  映射值只接受 fonts 内的实际文件名，需要自己放入对应字体，不读取系统字体；
  不使用 `.ttc` 或 `-VF.ttf`；
- `-Tag` 创建 `release-<版本>` 本地 tag，`-Push` 再推送该 tag；
- 输出在 `dist\PR2-<id>-<版本>.zip`，
  `id` 是分组 id（单语言分组沿用语言代码，如 `zh`；合包是 `latin`）；
- 每个 zip 根目录带 `manifest.json`：两个目标 exe、参考原文、翻译来源/AI 标记和逐文件 SHA-256，出包前会自校验，失败不出包；
- 所有包共用 `build\runtime`，都恒定带 `PR2HostMount.ps1` 和 `PR2Localization\host\Ascaron.Logging-2.6.dll`
  （不落根目录）；GOG 判版后从不读取这两项。

语言包/字体的统一构建入口是库：

```python
from build_artifacts import compile_pack, build_fonts
```

日常仍然用 `compile_pack.py` 或 `apply_patch.py`，不需要直接 import。

## build 目录

```
build\
├─ runtime\                 可直接整体复制到游戏目录
│  ├─ PR2LocalizationCore.dll
│  ├─ PR2Localization.exe
│  ├─ PR2LocalizationGUI.exe
│  ├─ Ascaron.Logging-2.6.dll   ← Steam 宿主代理（打包时从根目录移进 host\，不留在根）
│  ├─ PR2HostMount.ps1          ← 校验/备份/挂载/还原脚本（两版共用）
│  └─ PR2Localization\
│     ├─ host\             打包时把上面那份代理复制到这里，避免解压覆盖原版
│     ├─ packs\            累积的语言包
│     ├─ fonts\<语言>\      构建暂存；打包/部署时平铺到 PR2Localization\fonts
│     ├─ ui\               界面翻译
│     └─ logs\             运行时日志
├─ preview\                 给人查看，不参与发行
│  ├─ engine_text\<语言>.toml
│  └─ glossary\<语言>.md
└─ cache\                   可丢弃缓存
   └─ noto\                 Noto 字体缓存
```

`build\` 全部是产物，可以整个删掉重建。`runtime\` 是唯一的安装源；`preview\` 和 `cache\` 不进入发行包。

`build\runtime\PR2Localization\packs\locale.ini` 只在不存在时从模板创建，不会覆盖用户已选语言；
`locale.default.ini` 同样只在缺失时生成，作为部署/发行默认值。

## 脚本位置

根目录是日常入口，`src\` 下是低层实现：

| 位置 | 脚本 | 职责 |
|---|---|---|
| 根目录 | `build.ps1` | 一键构建：注入器 + 语言包 |
| 根目录 | `release.ps1` | 一键发版：构建 + 发行 zip + 可选 tag/push |
| 根目录 | `apply_patch.ps1` | 构建 + 部署 + 核对（PowerShell 7） |
| 根目录 | `check.ps1` | 跑项目检查/测试 |
| `src\` | `build_injector.ps1` | 用 cargo 编译 Rust DLL/启动器/代理（低层），包括 Steam 宿主代理 |
| `src\injector-rs\pr2_host_proxy\` | Cargo crate | 编译 `pr2_host_proxy.dll`，部署为 `Ascaron.Logging-2.6.dll` |
| `src\install\` | `PR2HostMount.ps1` | Steam 宿主 DLL 校验、备份、原子替换、还原（发行包内使用） |
| `src\` | `build_translation.ps1` | 编译单个语言包（低层，`-Lang`） |
| `src\` | `find_python.ps1` | 定位 Python（被上述脚本调用） |
| `src\` | `install\pr2ctl\` | Python 后端：检测、构建、部署、启动、设置 |

`src\tools\` 里的 Python 入口：

| 脚本 | 作用 |
|---|---|
| `pack/compile_pack.py` | 编译语言包、校验占位符 |
| `pack/build_artifacts.py` | 语言包/字体统一构建库 |
| `pack/apply_patch.py` | 一条命令构建并部署 |
| `pack/new_lang.py` | 新建语言 |
| `font/make_noto_fonts.py` | Noto 静态字重（映射的实际文件来源） |
| `font/build_cyr_fonts.py` | 俄语四个自建字体 |
| `font/extract_fonts.py` | 导出原版字体（测度量用） |
| `text/engine_text.py` | 由译文生成引擎文本（`build/preview/engine_text/`，只认 lang_rules 的 spec） |
| `text/lang_rules/spec.py` | 三段式接口：`Punctuation` / `Segmenter` / `Spacing` |
| `text/zh_pipeline.py` | 中文「分词前」：连词、人名、数字/破折号/`<n><n>` 空格 |
| `text/zh_space.py` | 中文分词与按字数成组补空格（spaCy / 机械兜底） |

中文补空格的分词器是**可选依赖**，不装也能构建：

- 装 spaCy + `zh_core_web_sm`（Python 3.9～3.13）。推荐在仓库根建一个专用
  venv，脚本会自动发现 `.venv-spacy`：

  ```powershell
  python -m venv .venv-spacy
  .venv-spacy\Scripts\python -m pip install spacy
  .venv-spacy\Scripts\python -m spacy download zh_core_web_sm
  ```

  也可以用环境变量 `PR2_SPACY_PYTHON` 指向别的解释器；
- 没有 spaCy 时 `zh_space` 退回按字数机械切（会切在词中间，终端会提示）。

### 不要用 jieba

**明确禁止**把 jieba 当分词依赖，也曾从代码里彻底移除（2026-11-17）。
理由是可查证的事实，不是口味：

- 最后一次提交停在 **2020-02-15**（`Update README.md update paddle link (#817)`），
  六年无更新；
- issues 累积 **649** 个、pull requests 58 个，基本无人处理；同类问题
  （`pkg_resources is deprecated`、Python 3.12 正则转义告警）长期挂着不修；
- 它的 `--HMM` 模式会把术语切在词中间，而修法只有「往用户词典里塞词」，
  词典本身又和停更的模型绑在一起，等于把分词质量锁死在一份 2020 年的语料上。

替代只有一条：spaCy + `zh_core_web_sm`。它按统计模型分词，维护活跃，
人名、地名、机构名不会被切开，也比 jieba 少一类「按词典硬匹配」的错误。
不要再因为「纯 Python、好装」把 jieba 加回 `requirements.txt` 或任何脚本里。
