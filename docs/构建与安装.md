# 构建与安装

## 入口

日常只需要（PowerShell 7 + Python 3.11+）：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

它会：

1. 在本机启动工作台服务；
2. 打开浏览器到安装页 `/install`；
3. 保留一个控制台窗口显示服务日志。

**不会自动编译。** 构建、部署、启动都在页面里点按钮触发。
关掉控制台窗口或 Ctrl+C 就停止服务。

> 另有一个发行版用的玩家界面 `PR2LocalizationGUI.exe`，见
> [发行版](发行版.md)。它不是这个开发工作台。

## 单条快路径（agent / 手工反馈用）

日常修正一条译文时，不必走完整构建链。`quick.py` 只做：

1. 按截图里的文本，在中文/英文/法文里找候选 hash；
2. 或按已知 hash 直接改 `src/translations/<lang>.toml` 的一条；
3. 调用 `compile_pack --no-fonts` 生成新的 `build/runtime/PR2Localization/packs/<lang>.txt`；
4. 只把这个 `.txt` 复制进游戏目录，不动 DLL、启动器和字体。

```powershell
# 先查候选，不改文件
python src\tools\pack\quick.py --lang zh --find "截图里看到的一句"

# 确认 hash 后改一条并部署
python src\tools\pack\quick.py --lang zh --id 0xc4bde7d1 --text "修正后的译文"

# 只改文件并生成 pack，不复制到游戏
python src\tools\pack\quick.py --lang zh --id 0xc4bde7d1 --text "修正后的译文" --no-deploy
```

`--find` 同时搜中文、英文、法文；带 `--text` 时只有唯一候选才允许自动写入，
否则必须显式给 `--id`。占位符/标签校验仍走 `shared\core\validate.py`：
错误始终拒绝；警告默认拒绝，确认无误可加 `--force`。

它**不做**全量 `check_breaks`、字体检查、运行时复制和全文件 SHA 核对。
这些仍属于发布前的完整构建。游戏启动时读取语言包，所以改完要重启游戏。

agent 需要结构化结果时加 `--json`；查找返回 `candidates`，写入返回
`id/pack/pack_sha256/deployed`。

## 安装向导

页面顶部是「安装与启动」里的五步向导，目标语言先选好：

| 步骤 | 做什么 |
|---|---|
| 1 准备游戏目录 | 选择游戏目录，或点「选择/检测」识别版本 |
| 2 准备字体 | 「导出原版」「检查 donor」；缺字体时给出提示 |
| 3 翻译内容 | 跳到译文编辑，检查目标语言还有多少未译 |
| 4 生成语言包 + 字体 | 调 `compile_pack` + 字体构建 |
| 5 安装并启动 | 部署到游戏目录，然后启动 |

向导只负责引导，下面的卡片仍然可以单独操作。

## 安装页的卡片

### 1 游戏目录

- 输入路径或「浏览…」；
- 「检测并记住」按 `PR2.exe` 的 SHA-256 识别已知版本，写进设置；
- 已记住的目录列在下方，可切换或移除；
- 状态显示版本、已装语言包、`locale.ini`。

设置默认在：

```
%LOCALAPPDATA%\PR2Localization\settings.json
```

可用环境变量 `PR2_SETTINGS` 改位置。里面只存路径和版本，不存译文。

### 2 构建与部署

| 按钮 | 作用 |
|---|---|
| 编译注入器（DLL + 启动器 + 代理） | 调 cargo，生成 `PR2LocalizationCore.dll`、`PR2Localization.exe`、`PR2LocalizationGUI.exe`、`PR2LocalizationProxy.dll`，部署时把后者改名为 `VERSION.dll` |
| 编译语言包 | 编译勾选的语言，并检查/重缝字体 |
| 部署到游戏目录 | 复制运行时、语言包、`PR2Localization/ui/`、`PR2Localization/fonts/<语言>/` |

部署特点：

- 只复制文件，不改 `PR2.exe`；
- 内容相同的文件按 SHA-256 跳过，不反复重写；
- 本次没勾选的语言包会从游戏目录移除；
- 字体放到 `PR2Localization/fonts/<语言>/`，**不覆盖根目录原版**；
- 语言包 `locale.ini` 不会被部署偷偷改掉。

### 3 启动

| 按钮 | 作用 |
|---|---|
| 语言下拉 | 从 `PR2Localization/packs/*.txt` 读取当前可用语言 |
| 设为游戏语言 | 写 `PR2Localization/packs/locale.ini` 的 `language=` |
| 启动游戏（已注入） | 用 `PR2Localization.exe` 按当前下拉语言启动 |
| 启动原版对比 | 直接启动 `PR2.exe`，不注入 |
| 打开译文编辑 | 切到译文编辑页 |

注意：**「启动游戏」不会自动写 `locale.ini`**，要持久保存请点「设为游戏语言」。
发行版 GUI 则是启动成功后自动写回。

## 语言怎么定的

运行时只有一种语言生效：

| 优先级 | 来源 | 范围 |
|---|---|---|
| 1 | 环境变量 `PR2_PACK_LANG` | 本次启动；`PR2Localization.exe --lang=xx` 设置 |
| 2 | `PR2Localization/packs/locale.ini` 的 `language=` | 持久默认 |
| 3 | DLL 内置兜底 `zh` | 连 ini 都没有时 |

因此：

- 安装页「设为游戏语言」= 写第 2 条；
- 安装页「启动游戏」= 只给本次传语言，不写文件；
- 发行版 `PR2LocalizationGUI.exe` 启动成功后写第 2 条；
- 直接双击 `PR2Localization.exe` 只读第 2 条；
- 直接运行 `PR2.exe` 不经过启动器，也不做版本检查。

## 版本识别

工作台用 `PR2.exe` 的 SHA-256 认出已知构建：

| 版本 | 说明 |
|---|---|
| GOG 英文 1.1.2.3 | ✅ 唯一支持，已实测 |
| GOG 法文 1.1.2.42 | ❌ 不支持，只用作翻译参照 |
| Steam 英文 1.1.2.3 | ❌ 不支持，CEG 下注入未生效 |

未支持的版本只用于识别/提示，不要部署，也不属于支持范围。

未知版本也可以记住，只是没有名字。版本名和哈希常量在
`src/tools/install/pr2ctl/base.py`。

## 字体

本机开发使用 **fontstitch 缝合**：

- 以 `assets/fonts/original/` 的原版拉丁字体为 base；
- 把当前译文用到的字从 donor 追加进去；
- 每个语言一套，输出 `build/runtime/PR2Localization/fonts/<语言>/`；
- 新字出现时自动重缝，缓存标记 `.stitch.json`；
- 字体失败不会让语言包构建失败。

发行版使用 **完整 Noto**，不缝合；详见 [发行版](发行版.md)。

```powershell
python src\tools\font\subset_fonts.py --lang zh
python src\tools\font\make_noto_fonts.py --lang zh --out <目录>
```

缝合字体只允许本机自用，不要上传或打包。详见 [字体与分发](字体与分发.md)。

## 译文编辑

和安装页在同一个工作台，顶部页签切换。

- 分页编辑，默认每页 100 条；
- 改过的条目跨页保留，点「保存」一起提交；
- 右侧参照列会标出「该版本无此条」；
- ＋ 添加语言：填代码、选模板，会生成 `src/translations/<代码>.toml`、
  `src/translations/<代码>.toml` 和 `presets/<代码>.toml`；
- 新语言要出现在安装页，需要重新加载工作台。

语言包元数据（显示名、GUI 语言、最低运行时）在：

```
src/packs/<代码>.toml
```

编译时写入语言包头部。旧语言包不再兼容，详见
[发行版](发行版.md)。

## 开发者命令

改完译文不想点页面：

```powershell
.\apply_patch.ps1                 # 构建 ja + zh，部署到上次的游戏目录
.\apply_patch.ps1 --langs ja      # 只弄日语
.\apply_patch.ps1 --launch        # 部署完直接启动
.\apply_patch.ps1 --dry-run       # 只打印计划
```

它按顺序做：

1. 归一化标点（只改标点；排版空格在编译期由 lang_rules 的 spec 补，不写回译文）；
2. `check_breaks --strict` 校验换行/占位符；
3. 编译语言包（默认含字体缝合）；
4. 部署到游戏目录；
5. 逐个文件比对 SHA-256。

### 一键构建

根目录 `build.ps1` 把注入器和语言包收成一个入口：

```powershell
.\build.ps1                         # 注入器 + 全部语言包（zh、ja）
.\build.ps1 -Target Packs           # 只编语言包
.\build.ps1 -Target Packs -Lang zh  # 只编中文
.\build.ps1 -Target Injector        # 只编 Rust 注入器
```

默认从 `src\translations\*.toml` 发现语言，所以新增语言后不需要改脚本。
低层脚本仍然保留，排查单步问题时可以直接跑：

```powershell
.\src\build_injector.ps1
.\src\build_translation.ps1 -Lang zh
.\src\build_translation.ps1 -Lang ja
```

### 一键发版

根目录 `release.ps1` 负责“构建运行时 → 生成 zip → 可选 tag/push”：

```powershell
.\release.ps1 -Version v1.0.0                 # 同时出 GOG 和 Steam 两套
.\release.ps1 -Version v1.0.0 -Edition gog    # 只出 GOG 包
.\release.ps1 -Version v1.0.0 -Edition steam  # 只出 Steam 包
.\release.ps1 -Version v1.0.0 -Lang zh
.\release.ps1 -Version v1.0.0 -Tag
.\release.ps1 -Version v1.0.0 -Tag -Push
```

- 默认语言同样从 `src\translations\*.toml` 发现；
- 默认同时生成 GOG 和 Steam 两套；`-Edition gog|steam|all` 控制；
- 默认先构建注入器，已有 `build\runtime` 时可加 `-SkipInjector`；
- 默认用 Noto 字体；自用测试可加 `-Fonts none` 避免生成大文件；
- `-Tag` 创建 `release-<版本>` 本地 tag，`-Push` 再推送该 tag；
- 输出在 `dist\PR2-<语言>-gog-<版本>.zip` 和 `dist\PR2-<语言>-steam-<版本>.zip`；
- 两类包共用 `build\runtime`，GOG 包在打包时过滤掉 `VERSION.dll`。

语言包/字体的统一构建入口是库：

```python
from build_artifacts import compile_pack, build_fonts
```

日常仍然用 `compile_pack.py` 或 `apply_patch.py`，不需要直接 import。

## build 目录

```
build\
├─ runtime\                 可直接整体复制到游戏目录
│  ├─ PR2LocalizationCore.dll
│  ├─ PR2Localization.exe
│  ├─ PR2LocalizationGUI.exe
│  ├─ VERSION.dll
│  └─ PR2Localization\
│     ├─ packs\            累积的语言包
│     ├─ fonts\<语言>\      缝合字体
│     ├─ ui\               界面翻译
│     └─ logs\             运行时日志
├─ preview\                 给人查看，不参与发行
│  ├─ engine_text\<语言>.toml
│  └─ glossary\<语言>.md
└─ cache\                   可丢弃缓存
   └─ noto\                 Noto 字体缓存
```

`build\` 全部是产物，可以整个删掉重建。`runtime\` 是唯一的安装源；`preview\` 和 `cache\` 不进入发行包。

`build\runtime\PR2Localization\packs\locale.ini` 只在不存在时从模板创建，不会覆盖用户已选语言。

## 脚本位置

根目录是日常入口，`src\` 下是低层实现：

| 位置 | 脚本 | 职责 |
|---|---|---|
| 根目录 | `start.ps1` | 启动本地工作台服务（PowerShell 7） |
| 根目录 | `build.ps1` | 一键构建：注入器 + 语言包 |
| 根目录 | `release.ps1` | 一键发版：构建 + 发行 zip + 可选 tag/push |
| 根目录 | `apply_patch.ps1` | 构建 + 部署 + 核对（PowerShell 7） |
| 根目录 | `check.ps1` | 跑项目检查/测试 |
| `src\` | `build_injector.ps1` | 用 cargo 编译 Rust DLL/启动器/代理，代理构建名为 `PR2LocalizationProxy.dll`，部署时改名为 `VERSION.dll`（低层） |
| `src\` | `build_translation.ps1` | 编译单个语言包（低层，`-Lang`） |
| `src\` | `find_python.ps1` | 定位 Python（被上述脚本调用） |
| `src\editor\` | `StartEditor.ps1` | 只启动编辑器前端/后端 |

`src\tools\` 里的 Python 入口：

| 脚本 | 作用 |
|---|---|
| `pack/compile_pack.py` | 编译语言包、校验占位符 |
| `pack/build_artifacts.py` | 语言包/字体统一构建库 |
| `pack/apply_patch.py` | 一条命令构建并部署 |
| `pack/new_lang.py` | 新建语言 |
| `font/subset_fonts.py` | 缝合字体 |
| `font/make_noto_fonts.py` | 发行版 Noto 字体 |
| `text/engine_text.py` | 由译文生成引擎文本（`build/preview/engine_text/`，只认 lang_rules 的 spec） |
| `text/lang_rules/spec.py` | 三段式接口：`Punctuation` / `Segmenter` / `Spacing` |
| `text/zh_pipeline.py` | 中文「分词前」：连词、人名、数字/破折号/`<n><n>` 空格 |
| `text/zh_space.py` | 中文分词与按字数成组补空格（spaCy / jieba / 机械兜底） |

中文补空格的分词器是**可选依赖**，不装也能构建：

- `pip install jieba`（已装，纯 Python，当前默认用它）；
- 想更准可装 spaCy + `zh_core_web_sm`，需要 Python 3.11，
  用环境变量 `PR2_SPACY_PYTHON` 指向那个解释器；
- 两者都没有时 `zh_space` 退回按字数机械切（会切在词中间，终端会提示）。

## 服务状态

安装页底部「服务状态」显示：

- 当前服务 pid、端口、运行时长、Python 版本；
- 8777–8800 范围内的其它实例，可一键停止；
- 接口：`/api/health`、`/api/server/instances`、`/api/server/stop`。

命令行：

```powershell
.\start.ps1 -Status
python src\tools\install\server_status.py --stop 8779
```
