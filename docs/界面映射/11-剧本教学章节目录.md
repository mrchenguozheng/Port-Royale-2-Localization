# 界面映射 · 剧本教学章节目录（推断）

> 本卷表格里的标记**故意不带方括号**：排查包扫描时把「方括号标记 + 同一行的 0x 键」当成已查清，写上就会被清掉。
> 括号里的值由 `compile_pack.mark_map()` 直接算出（4 位起步，撞号才加长），与包上印的一模一样，照着认就行。
> 什么时候把这些行改成带方括号的正式行：等其中某条真在屏上见过一次，确认内容与这里写的一致之后。

## 推断方法与可信度

1. **键连续**：一整章教学在库里是一段连续键区间，这是本库的固定排布（第 1 章 `0x2efebfdd`–`e6` 十条已实机验证）。
2. **文本顺序自洽**：连续十条读下来必须是「先做什么 → 看到什么 → 再做什么」的单向推进，且每条的「你刚做的事」与上一条的「现在去做」能接上。
3. **界面归属已知**：教学正文一律走屏幕左上那块「提示」小窗（城名 + 游戏内日期 + 正文），收尾走「剧本目标已完成」大窗。
4. 可信度分级：`实测`＝逐条有实机标记；`高`＝键连续 + 顺序自洽 + 与相邻章的衔接词对得上（如上一章末「下一步是…」）；`中高`／`中`＝键连续但章界可能错位，或多条内容平行（不同剧本的同类教学）。

## 五章连起来是什么

`剧本 1` 只教**界面与船**（巡礼 → 船队条与海图 → 买船）；`剧本 2` 教**买卖**（码头价格 → 圣玛尔塔价差 → 贸易记录与建筑许可）；`剧本 3` 教**生产**（殖民城镇 → 建造 → 种植园成本）；`剧本 4` 教**海战**（武装 → 总督委托 → 炮击与登船）。这与剧本完成窗 `0x35392fbd` 那句「下一节讲的是如何靠贸易赚到钱」正好对上：第 1 章收尾指的第 2 章就是 `FEDB` 这一串。

## 不是教学的两类连续键，别当章节

- **百科长文**：`0xd4cd0fae`–`fb7`、`0xd4cd101f`–`1028` 这类十条一段全是历史/海盗长文，是百科书一页十条的排布，段落之间没有「步骤」关系。
- **对话变体**：`0x1629fb20`–`22`、`0xcb8dd6d9`–`db` 这类三条一段是同一个人物的不同问候/不同委托状态，随机取一条，不是章节推进。

## 剧本 5 以后：靠「开头句 + 完成句」锚定，只能给主题归属（推断，可信度中）

为什么推不出确定顺序：第 1–4 章那种「一整章十条连续键」在剧本 5 以后**不存在**。
逐条扫全库，教学味的句子到这之后就全是**孤立键**（前后邻居是别的东西），「键连续」这条主判据直接失效，
剩下的只能靠两种锚点：

1. **剧本开头**：这里要分清两样东西——剧本**详情页**的介绍（`Introductory Scenario<n><n>In this scenario, you will…`，只在选单右侧读）与游戏里真弹出来的**开场故事框**（带 `ELGRECO_26x26` 字体标签、末尾内嵌「剧本目标」）。前者只说方向，后者才是本章第一段；而剧本 2 这张实机截图证明两者正文是**不同的键**（详情 `0x32f1c30f`，开场框 `0x19f413a1`）。
2. **剧本完成窗正文**：`Congratulations! You have successfully completed…`，句子里会把本章做过的事再复述一遍。

把这两头对上，中间那些孤立的教学句就能按**主题**归到某个剧本，但**先后顺序只能靠句内的「Now / next / Very good」线索猜**，
所以本卷不给它们排序号，只给归属。真要排顺序，等你在屏上跑到那一章，debug 包里这些孤立键各自带唯一标记，一条一条对即可。

## 剧本框总表：48 条（每条自带「剧本目标」与目标句）

这一节回答「拿开头能不能推后面」：**能，而且不用打通**。库里每个剧本阶段都是一条带 `<f:fonts/ELGRECO_26x26aaFHk.res>` 标签的长文，结构固定为「开场叙述 ＋ `<n>` ＋ 剧本目标 ＋ 目标句」。
所以搜这一个字体标签就能把全部 48 条剧本框枚举出来，每条的目标句就是那一段要你做的事，
前一段的目标往往正是后一段开头的「干得好！」——这就是接续关系。
