# 流水线总览

四段：**参照层 → 译文层 → 校验层 → 出包层**。每段只做自己那件事，越界就会把上一段
的问题变成下一段的规格。

```text
  原版 en.gog ─┐                        ┌─ 译文骨架（new_lang --from en）
  官方 fr.gog ─┼→ 参照层（六份 clean）─→ │  分批翻译 / 零售导入 / 诗谜标注
  四家零售 ────┘       build/ref/clean    └─ 校验层（lint / lang / ref / line / gaps）
                                              ↓
                                         出包层（compile_pack → packs/<语言>.txt）
```

## 1 参照层（一次性，参照变了才重跑）

入口 `src\tools\analysis\ref_clean.py`。只动结构，一个字都不改。

| 步骤 | 命令 | 依赖 | 产物 |
|---|---|---|---|
| en-clean | `--ref en.gog_1.1.2.3 --patch src\data\qa\ref_patch\en.json --align-empty --write` | 无 | `build\ref\clean\en-clean.toml`（3548，改 2） |
| fr-clean | `--ref fr.gog_1.1.2.42 --base en-clean --patch src\data\qa\ref_patch\fr.json --align-empty --write` | en-clean | `fr-clean.toml`（3571，改 6） |
| 四家零售 | `--ref <x>.retail-1.0.0 --base en-clean --add-only --align-empty --write` | en-clean | `de/es/pl/ru-clean.toml` |
| de 额外 | 上一条再加 `--align-idm` | en-clean | de 15 条 2004 竞赛日志退回 `IDM_` 键名 |

要点：

- **en-clean 必须最先**。fr 与四家零售的 `--base` 都是它，顺序倒了就对不上。
- 零售加 `--add-only`：只补不删、只补在严档句末、缺口超 2 处交人。零售的段落是它
  自己的排版，按 en 强度削会把整段挤成一行。
- `--align-empty`：`+++EMPTY+++` 按多数票定，缺键不投票。清完六份占位状态 0 冲突。
- 切点写进 `src\data\qa\ref_patch\<语言>.json`（`{id: [[old, new]]}`，old 必须唯一命中）。
  补丁在结构对齐之前上，工具内部已保证。
- 产物在 `build\`（gitignored），随时可重建；`translate.py` 的 `lang_path()` 已默认
  优先读这些 clean 文件，找不到才退回 `src\orig` 原件。

## 2 译文层

| 环节 | 命令 | 说明 |
|---|---|---|
| 骨架 | `python src\tools\pack\new_lang.py --new-lang zh --from en` | 条目数与顺序必须与 en 一致 |
| 进度 | `python src\tools\translate.py status --lang zh` | 只算「可译」条目，`+++EMPTY+++` 与 `IDM_` 不计 |
| 切批 | `python src\tools\pack\split_batches.py --lang ko` | 落到 `build\qa\batches\ko\` |
| 合并 | `python src\tools\pack\merge_batches.py --lang ko` | 任一条 E 级整批不写 |
| 落盘 | `python src\tools\translate.py apply --lang ko --map build\x.json` | 写盘前跑令牌/标签检查，不合格拒绝 |
| 零售导入 | `retail_import.py --lang es --ref es.retail-1.0.0 --clean-ref` → 拿清洁版 `--ref --repair --write` | 三步走，中间必须过清洁版 |
| 诗谜标注 | `analysis\riddle_marks.py --lang ko --from ko` | 搬运 `answer/group/level/certainty/source` |
| 术语 | `analysis\terms_seed.py --lang ko` | 起草 `src\data\terms\ko.toml` |

## 3 校验层

| 检查 | 命令 | 查什么 |
|---|---|---|
| 译文规范 | `analysis\text_lint.py --lang zh --strict` | E/W 级定则（令牌、标签、空白、标点） |
| 外语形态 | `analysis\lang_check.py --lang zh` | 语法、拼写、复合词；`--spell-only` 只查拼写 |
| 断行 | `analysis\line_run.py --lang zh` | 断完最长段是否超上限 |
| 不译清单 | `analysis\keep_audit.py --lang zh` | 有意不译的条目是否还在清单上 |
| 参照自身 | `analysis\ref_check.py --ref <参照路径>` | 参照自己哪几条是坏的（只收路径，不认短名） |
| 源缺失 | `translate.py gaps --lang zh` | en 是占位/键名而译文有实文 |
| 术语 | `tools\terms_check.py --lang zh` | 术语表与译文是否一致 |
| 全量门禁 | `.\check.ps1 -NoPause` | 上面全部 + 单测（提交前必跑） |

分级处置：E 必须改；W 要豁免就落 `src\data\lint_ok\<语言>.txt` 并写理由；结构类交
`ref_clean --patch`；令牌缺成分是内容缺口，只能重译，不许猜。

## 4 出包层

| 环节 | 命令 | 产物 |
|---|---|---|
| 编译 | `python src\tools\pack\compile_pack.py --lang zh --strict --no-fonts` | `build\runtime\PR2Localization\packs\zh.txt` |
| 预览 | `python src\tools\text\engine_text.py --lang zh` | `build\preview\engine_text\zh.toml` |
| 发行 | `python src\tools\pack\make_release.py` | `dist\` 两个 zip + `SHA256SUMS.txt`（见[发行规范](发行规范.md)） |

## 顺序不能反的四处

1. **en-clean → fr-clean → 四家零售**：后五份的基准都是 en-clean。
2. **补丁 → 结构对齐**：自动挑的 `<n>` 切点会先占位，补丁的 old 串就找不到了。
3. **原始零售 → 清洁版 → 以清洁版为基准**：直接拿原始零售 `--write` 会把手工修过的
   行按零售原文盖回去。
4. **参照清洁 → 译文校验**：参照没清就先校验，等于拿缺陷当规格。

## 各层不做什么

- 参照层不改字：措辞、语体、标点全留原样，改字是重译。
- 译文层不猜令牌成分：缺 `%3`、缺 `@A$Amount$` 就进 hold 名单，不许编。
- 校验层不做语义判断：只认机械判据，口味问题记口径，不记「错」。
- 出包层不改数据：只读译文与参照，产出物落 `build\`/`dist\`。
